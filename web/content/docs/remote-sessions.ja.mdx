---
title: リモートセッションの共有
description: SSH または Tailscale で同じリモート端末に接続し、切断後もジョブを続行します。
---

`zshell-server` は macOS または Linux ホスト上でシェルとジョブを保持します。Zshell の両方の端末バックエンドで利用でき、クライアントを終了しても処理は続きます。再接続すると画面、スクロール履歴、カーソル、端末モードが復元されます。

## インストール [#install]

**リモートホスト…**で SSH 経由で**サーバーをインストール / 更新**します。同じアーキテクチャの Mac は内蔵実行ファイルを使います。Linux は対応する `zshell-server` を選択してください。転送と互換性を確認してから置き換えます。起動中の daemon は再起動まで旧版を使い、再起動で端末ジョブが終了します。ホストで直接ビルドもできます：

```sh
cargo build --locked --release --manifest-path remote/Cargo.toml
install -d "$HOME/.local/bin"
install -m 755 remote/target/release/zshell-server "$HOME/.local/bin/zshell-server"
```

接続者はサーバーを実行するアカウントのシェルとファイルを操作できます。macOS と Linux に対応します。

## SSH [#ssh]

通常の SSH でホスト鍵と公開鍵または agent 認証を確認します。

```sh
ssh devbox true
```

サイドバーのネットワークメニューからリモートホストを開き、名前、`ssh://me@devbox:22` または SSH エイリアス、`~/.local/bin/zshell-server` を入力します。ホストへの接続は既存のプロジェクトとセッションを読み込みます。`~/repo` などのディレクトリを指定してリモートプロジェクトを開くと、新しいシェルが作成されます。空白を含むパス、新規タブ、分割ペインにも対応します。

daemon は SSH 経由で自動起動します。OpenSSH 設定、鍵、agent、信頼済みホスト鍵を使用し、未知の鍵や認証失敗はエラーになります。ファイルと Git は同じホストへの SSH を使用するため、Tailscale 端末でも別途 SSH 接続が必要です。リモートパスで Mac のファイルにアクセスすることはありません。`ZSHELL_SSH_CONFIG_FILE` には別の読み取り可能な設定ファイルの絶対パスを指定できます。

## Tailscale [#tailscale]

両方の端末を Tailscale に接続し、セッション作成前にプライベートリスナーを起動します。

```sh
zshell-server serve --listen tailscale://:7373
```

`tailscale://devbox:7373` を追加します。MagicDNS と Tailscale IPv4/IPv6 に対応し、公開アドレスは拒否します。既定ではホスト所有者のタグなし端末のみ許可します。`--allow-user` は完全一致する別のログイン名を許可しますが、タグ付きクライアントは拒否します。同一マシンからは SSH を使用してください。Tailnet ACL も適用され、接続者はサービスの Unix アカウントを操作できます。

この Mac を共有するには Tailscale にログインし、**リモートホスト…**の**この Mac を共有**を選びます。ポートと許可する完全なログイン名を設定できます。明示的に開始したときだけ共有し、**共有を停止**または Zshell の終了で共有セッションを終了します。

## 共有と終了 [#sharing]

全クライアントが同じ出力を受信します。端末にフォーカスするか制御権を取得すると、そのクライアントが入力とサイズを制御します。切断時は最も早く接続した残りのクライアントに移ります。情報パネルで状態、接続数、制御権を確認し、切り離しと再接続を操作できます。通信障害は自動再試行し、切断中の入力は破棄します。保存済みレイアウトはリモート UUID を使って同じジョブに戻ります。

ペイン、プロジェクト、ウインドウを閉じる操作と、両方のアプリ終了操作は接続だけを切り離します。リモートセッション終了は確認後、全クライアントのシェルとジョブを停止します。ホストでは `zshell-server terminate --project ~/repo --session UUID` も使えます。

Mac がスリープから復帰すると、共有リモートセッションは接続を確認し、必要に応じて同じリモートジョブに再接続します。手動で切り離したセッションはそのままです。

## ファイルと画像 [#paste]

通常のファイルやスクリーンショットをコピーしてリモートペインに貼り付けます。ホストの非公開ディレクトリへ転送後、シェルに合う引用パスを挿入します。1 回 32 ファイル、各 32 MiB、合計 64 MiB までで、フォルダーとシンボリックリンクは不可です。共有セッションの転送は 7 日間保持します。通常の Unix SSH ペインも対応します。

## リモート Agent の会話 [#agents]

リモート Agent の動作、進捗、承認待ち、完了は既存のペイン状態と通知に表示します。**Agent 会話履歴**にはホストの Claude Code、Codex、OpenCode、Pi の会話が含まれます。再開は生存中の会話へ接続するか、元のホストとディレクトリで正確な会話を起動します。会話履歴は daemon 再起動後も残りますが、実行ジョブとスクロール履歴は残りません。元のプログラム、設定やセッションファイルが必要です。

## 制限 [#limits]

daemon の生存中だけ保持され、ホスト再起動や daemon の再起動・クラッシュには対応しません。失われたセッションはエラーを表示し、新しいシェルに置き換えません。上限は 128 セッション、16 MiB のスナップショット、クライアントごとに 1 MiB のライブキューです。遅い接続は他を妨げず切断され、履歴はホストのメモリ内に残ります。サービスの設定と CLI は[サーバーの説明](https://github.com/wzz6423/zshell/tree/main/remote)を参照してください。

## ブラウザアクセス [#browser-access]

**設定 → ブラウザアクセス** から、この Mac のローカルターミナルペインをブラウザで操作できます。既定では無効です。有効化後に新しいローカルペインを開き、ローカルページを使うか、プライベート IPv4 LAN/Tailscale インターフェイスと HTTPS ポートを明示的に選択します。既存のペインは現在のプロセスを維持します。ブラウザは Mac のペインへ接続するだけで、shell の作成やリモートホストへの接続はできません。

ローカル HTTP ページは通常、設定した HTTPS ポートの次のポート（既定は `7444`）を使います。スリープ復帰、再試行、再起動でもアドレスと承認を維持します。ポートが使用中の場合は続く 7 個のローカルポートを順に試し、`65535` の後は `1024` に戻ります。アドレスが変わる場合は再ペアリングが必要です。アクセスがオフでも保存済みクライアントを表示して取り消せます。32 クライアントの上限に達したら、新規承認の前に既存の承認を取り消してください。

別の端末では、TLS 証明書を書き出して設定のフィンガープリントを照合し、クライアントで信頼してから HTTPS アドレスを開きます。クライアント名を入力して **ペアリングを要求** を選び、2 分以内に Mac に表示されたコード、アドレス、オリジンを照合して **承認** します。認証は最大 90 日で、正確なアドレスとプロトコルに限定されます。**承認を取り消す** または **すべてのクライアントの承認を取り消す** と、接続と認証情報は直ちに無効になります。

セッションを選択すると、現在の画面と ANSI 色・Unicode を含むライブ出力が表示され、同じプロセスへ入力できます。Mac とブラウザで入力を共有します。**ブラウザに合わせてターミナルをリサイズ** を選ばない限り、サイズは Mac が管理します。切断中の入力は破棄し、再接続は同じ存続セッションへ戻ります。再読み込み時はそのタブの認証情報を保持し、タブを閉じるか **このブラウザを忘れる** で削除します。アドレス変更時は再ペアリングが必要です。

無効化、Mac のスリープ、Zshell の終了でブラウザサービスは停止します。ペインを閉じるとプロセスも終了します。アプリ終了時の shell の保持は `terminal.preserve-sessions` に従い、ブラウザアクセスは設定を変更しません。Zshell を開き直すと存続ペインへ戻れます。ホストの再起動やデーモン終了で shell は終了します。出力キューには上限があり、遅いクライアントを切断して Mac の停止を防ぎます。ページはアプリに同梱され、CDN は使いません。

以前の Zshell が保持したセッションが動いている場合、ブラウザアクセスはすべてのセッションを終了して Zshell を開き直すよう案内します。選択するまでは既存のジョブを維持します。
