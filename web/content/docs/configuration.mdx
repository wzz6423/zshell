Most persistent Zshell settings live in one file:

```
~/.config/zshell/config.toml
```

The Settings window (<kbd>Cmd</kbd>+<kbd>,</kbd>) writes this same file. A few
macOS-owned settings—language and automatic updates—live elsewhere and are
listed at the end of this page.

New configurations enable Vim command hints, session history restoration, and
failed-command notifications. Automatic update downloads are also enabled by
default. Existing configurations and saved choices are preserved.

In **Settings → Terminal**, input controls are under **Input**, recording and history access under **History**, and command alerts and notification history under **Notifications**. **Cursor** and **Background** are in **Settings → Appearance**.

Dependent controls are hidden while their parent feature is off; saved values are kept. This applies to Quick Terminal controls, agent resume and notifications, font stroke strength, focus-ring opacity, Git proxy address, and browser filter lists and status. Background blur appears only with a translucent background while macOS Reduce Transparency is off.

## How the file behaves

Worth knowing before you hand-edit:

- **Changes are read while Zshell is running.** Valid external edits apply automatically; settings marked for new terminals still need a new pane. Unreadable or malformed edits retain the last valid settings. An intentionally empty file restores defaults after a short delay.
- **Zshell rewrites it whenever a file-backed setting changes.** The file is
  regenerated from scratch, so your comments and unknown keys are lost the
  next time you use one of those controls. Pick one editor for the file, or
  keep an authoritative copy in your dotfiles.
- **Most default values are omitted.** `font-size`, `terminal.vim-command-hints`, `terminal.restore-history`, `terminal.notify-on-error`, `terminal.prompt-queue-enabled`, `terminal.prompt-queue-auto-dispatch` are always written. Removing `terminal.vim-command-hints`, `terminal.restore-history`, or `terminal.notify-on-error` from an existing file disables that feature. Removing `terminal.prompt-queue-enabled` restores its default `true`; removing `terminal.prompt-queue-auto-dispatch` restores its default `false`. Removing other keys restores their defaults.
- **The parser is deliberately small.** It supports flat keys, dotted keys,
  `[table]` headers, `#` comments, and string/number/boolean values. It does not
  support arrays, inline tables, or multi-line strings.
- **Bad values fall back safely.** An out-of-range size, unknown backend, or
  misspelled theme does not stop Zshell from launching.

Symbolic links to a file or directory are preserved when Settings saves: Zshell updates the target atomically and keeps its permissions. External edits do not rewrite comments or unknown keys; a subsequent Settings save still regenerates the file as described above.

## Application presence [#application-presence]

### `app-presence`

`"dock"` · `"dock-and-menu-bar"` · `"menu-bar"` — default `"dock"`

Choose **Settings → General → Show Zshell in** to switch immediately. `"dock"` shows only the Dock icon. `"dock-and-menu-bar"` shows both icons. `"menu-bar"` shows only the menu bar icon.

The menu bar opens the current workspace, Quick Terminal, Settings, and the update checker. With either menu bar mode, closing the last workspace window hides it while its terminals and jobs keep running. **Open Workspace** returns to that same window, project, and session. Closing another workspace window, a pane, or a project still ends its tasks. Explicit **Quit** keeps following `terminal.preserve-sessions`; **Quit and End All Sessions** ends them. The mode is saved across launches.

## Keep computer awake [#keep-computer-awake]

### `keep-awake`

`"off"` · `"on"` · `"agents"` — default `"off"`

Choose **Settings → General → Keep computer awake** or **Zshell → Keep computer awake**. `"off"` allows automatic sleep, `"on"` prevents automatic system sleep while Zshell runs, and `"agents"` prevents it only while a local agent is working.

In `"agents"` mode, every local terminal pane counts, including background projects, other windows, and hidden or zoomed splits. Remote agents do not count. Waiting, idle, and completed agents allow sleep when no other local agent is working, and closing the last working pane releases sleep prevention. `"on"` continues preventing automatic sleep while Zshell runs. Choosing Off or quitting Zshell releases sleep prevention in every mode, including when terminal sessions are preserved.

The Settings row shows whether sleep prevention is active or unavailable. Displays can sleep, and manual sleep, lid close, and low-battery sleep keep following macOS policy.

## Appearance

### `theme`

`"system"` · `"light"` · `"dark"` — default `"system"`

Chooses the app appearance. `"system"` follows macOS; the other two pin Zshell
to one appearance.

### `theme-dark` and `theme-light`

string — defaults `"Default Dark"` and `"Default Light"`

The color theme for each appearance. A theme recolors terminal panes, window
chrome, sidebars, the editor, and diffs together. The built-in defaults keep
Zshell's translucent sidebar; other themes paint it to match their palette.

Settings lists the curated theme catalog shared by both terminal backends. A
hand-written name must match one of those display names exactly, including
case, or Zshell falls back to the corresponding default.

### `terminal.minimum-contrast` [#terminalminimum-contrast]

`1`–`21` · `3`

Choose **Settings → Appearance → Colors → Minimum contrast** to adjust terminal text readability from `1` to `21` (default `3`). Set `1` to keep original ANSI colors. Both backends update open terminals and Quick Terminal without restarting their shells; terminal profiles still use their own palettes. Emoji and image pixels keep their original colors. Selection and cursor rendering keep each backend’s native readability policy. For backgrounds that cannot reach the requested ratio, each backend uses its best available readable color. Transparent terminals use the resolved cell background, so the final desktop composite may have a different contrast.

### `toolbar.visibility`

`"hide"` · `"auto"` · `"always"` — default `"hide"`

Controls the compact toolbar below the active tab:

- `"hide"` keeps it out of the window.
- `"auto"` shows it only when the project directory is a Git repository.
- `"always"` keeps its Git entry point visible in every project, including a
  **No Git Repository** state.

See [The Git toolbar](/en/docs/git#the-git-toolbar) for what it shows.

## Text

### `font-family`

string — default `""`, meaning the bundled JetBrains Mono

The terminal, editor, and diff viewer share this Latin family. Give a family
name, not a face: `"IBM Plex Mono"`, not `"IBM Plex Mono Regular"`. Unknown or
non-monospace families fall back to the bundled default.

Terminal fallback order is the Latin family, the optional CJK fallback below,
the bundled Symbols Nerd Font, then the backend's system fallback. The editor
and diff viewer continue to use their normal macOS/WebKit fallback.

### `terminal.font-fallback-family`

string — default `""`, meaning backend/system fallback

Adds one installed CJK family to the terminal's ordered fallback chain. The
Settings picker includes families containing representative Chinese, Japanese,
or Korean glyphs; it does not require them to be strictly monospace because
they only supply glyphs missing from the primary Latin face.

### `font-size`

number, 8–32 — default `13`

The shared terminal, editor, and diff font size in points. This is the one key
Zshell writes even when it has the default value.

### `interface.scale`

number, 0.9–1.5 — default `1`

Scales tabs, icons, buttons, sidebars, and the rest of the application interface.
Terminal, editor, and diff content keep the font size configured separately above.

### `sidebar.font-size`

number, 9–24 — default `14`

The base text size for both sidebars. Section headings, rows, metadata, and
controls keep their relative hierarchy as the base changes.

### `sidebar.double-click-new-session`

boolean — default `true`

Double-click empty sidebar space to create a session in the selected project. If no project is selected, it creates a project. Row clicks and drags keep their usual actions.

### `terminal.font-ligatures` [#terminalfont-ligatures]

boolean — default `true`

Choose **Settings → Appearance → Font ligatures** to enable or disable optional ligatures on both terminal backends. Disabling it overrides `calt`, `liga`, `clig`, `dlig`, and `hlig` while keeping required script shaping. The original characters, terminal columns, cursor, and selection stay unchanged.

### `terminal.font-features` [#terminalfont-features]

string — default `""`, using the font’s defaults

Set **OpenType features** in the same Font group. Separate four-character tags with commas or whitespace: `-calt` disables contextual alternates, `ss01` enables stylistic set 1, and `zero=1` enables the font’s alternate zero. `+liga` and `liga=1` also enable a feature. Later entries for the same tag win. The ligature switch takes priority for its five tags.

Changes apply immediately to open terminals and the font preview. Both backends use features supported by the selected font; unsupported tags have no effect. Invalid input keeps the last valid value in Settings, and an invalid external value uses font defaults. Reset to Defaults restores an empty feature list and enabled ligatures.

### `terminal.font-thicken`

boolean — default `false`

Renders terminal glyphs with slightly heavier strokes, similar to classic
macOS font smoothing. Both backends honor it, and the Settings preview shows
the result. Older `font-thicken` configs are still read, then rewritten using
the current dotted key.

### `terminal.font-thicken-strength`

integer, 0–255 — default `255`

Controls thickening while `terminal.font-thicken` is true. Zero is the lightest
available thickening, not off. Ghostty uses its native macOS strength; Alacritty
maps the same range to a CoreText stroke, so the direction and endpoints match
but rasterized pixels can differ.

### `terminal.cell-width`

number, 0.75–2 — default `1`

Changes terminal column spacing in **Settings → Appearance → Font → Cell width**. The default is 100%; values use whole percentages. Both backends update open terminals immediately, including the PTY column count, cursor, selection, and keyboard hints. Glyph size stays unchanged, and wide characters still occupy two columns. Pixel rounding can produce different effective steps on each backend. Invalid values restore 100%. Editor and diff spacing are unaffected.

### `terminal.line-height`

number, 0.75–2 — default `1`

Multiplies each terminal backend's natural cell height while keeping glyphs
vertically centered. It changes terminal rows only, not editor or diff spacing.

Zshell does not expose a base font-weight control. Ghostty selects named styles
or variation axes while Alacritty/CoreText resolves regular and bold faces by
traits; a single shared value would not preserve regular/bold distinction or
fallback weights consistently across static and variable fonts.

### `terminal.padding-color` [#terminalpadding-color]

`"background"` · `"extend"` · `"always"` — `"extend"`

Choose **Settings → Appearance → Background → Padding color**. `"background"` uses the terminal theme background in the padding. `"extend"` extends the nearest cell background, but keeps the top or bottom padding on the theme background when that row contains a default-background cell, a shell prompt, or a Powerline separator. `"always"` extends every edge without those checks. Blank bottom rows remain on their own background; a colored row above them does not fill the bottom padding. Changes apply immediately to open terminals with both backends. With translucency, default backgrounds keep their opacity while explicit cell backgrounds and their extensions remain opaque.

### `editor.wrap-lines`

boolean — default `true`

Soft-wraps long lines to the pane width in the [file editor](/en/docs/files).
When false, long lines scroll horizontally. It does not change wrapping in a
terminal or diff.

### `editor.diff-wrap-lines` [#editordiff-wrap-lines]

boolean — default `false`

Choose **Settings → Editor → Wrap lines to diff width** or the word-wrap button in the diff toolbar. Long lines wrap to the pane width in unified and split layouts, editable worktree changes, historical diffs, and PR comments. The choice applies immediately to all open diffs and is saved across launches. Turning it off restores horizontal scrolling. It does not change file-editor or terminal wrapping.

### `editor.protect-saves`

boolean — default `true`

Checks for changes made by another program before saving a file or editable worktree diff. If the disk version changed, compare it with your draft, reload from disk, keep the draft, or explicitly overwrite the file. Turning this off allows saves to replace external changes without a conflict prompt.

### `editor.recover-drafts`

boolean — default `true`

Zshell backs up unsaved local file and editable worktree diff changes by default. After an unexpected exit, reopened panes restore their drafts, selections, and layout. Recover other backups from **File → Recover Drafts…** or **Settings → Editor → Recover Drafts…**; select a backup, review its contents, and choose **Restore Draft**. Restoring opens an unsaved editor and never changes the file on disk. Saving still checks for external changes using the version from before your edits.

Control backups with **Settings → Editor → Back up unsaved drafts** or `editor.recover-drafts`. Turning it off stops new backups and automatic recovery, while keeping existing backups available for manual recovery or deletion. **Delete Backup** removes only the selected backup; open edits remain. Saving successfully or choosing **Don’t Save** for a completed close removes the backup. Backups are private files on this Mac, limited to 32 drafts and 128 MiB, recoverable for up to 30 days. Capacity limits may delete older backups sooner. Files and edited text larger than 5 MiB are excluded.

Zshell deletes expired backups at startup and every hour while running, even when backups are off. If Zshell is closed, expired files remain on disk until the next launch.

## Terminal

### `terminal.preserve-sessions`

boolean — default `false`

Keeps shells, coding agents, and development servers in newly opened terminals
running after you quit Zshell. Reopening connects to the same live process and
restores its terminal screen and input modes with either backend. Restored shell
prompts use the configured cursor immediately, including when the background
daemon has remained running through an app update. The daemon keeps bounded
screen history in memory; it does not survive a macOS restart. If
the PTY is no longer alive, the pane opens a fresh shell instead.
When a persistent terminal's main process exits, Zshell also ends the remaining
jobs in that terminal, including jobs that ignore hangup signals.

Closing a pane, project, or window still ends its tasks, except for the last
workspace window in a [menu bar mode](#application-presence). Use **Zshell → Quit and
End All Sessions**, or turn this setting off before quitting, to end every
background session, including a hidden Quick Terminal. In reuse mode, hiding the Quick Terminal
keeps its shells alive; this setting controls whether newly opened reusable panes
also survive quitting Zshell. Fresh workspaces end when hidden.

The CLI in a retained shell reconnects to its original terminal when Zshell
reopens. It is unavailable while the GUI is closed. The stable CLI launcher is
updated on reconnect; removing a development build can make the CLI unavailable
until another build of Zshell reopens the session. Terminal image placements and
backend-specific graphics are not restored; applications can redraw them.

### `terminal.startup-program` / `terminal.startup-arguments`

strings — default unset

Choose the executable and argument vector used by terminals created from then
on. When `terminal.startup-program` is absent, Zshell keeps using the account
login shell with `-l`. The program must be an executable absolute path; a
missing or non-executable path falls back to the login shell instead of opening
a dead pane.

`terminal.startup-arguments` is split into arguments without invoking a shell.
Quotes and backslashes preserve boundaries, including spaces and empty
arguments, but variables, globs, and command substitutions are not expanded.
Invalid quoting also falls back to the login shell. An explicit argv supplied by
the Zshell CLI still takes precedence for that terminal.

### `terminal.new-session-directory` [#terminalnew-session-directory]

`"current"` · `"project"` · `"home"` · `"custom"` — default `"current"`

Choose **Settings → Terminal → New session directory**. Current uses the active local shell's directory, including the first terminal of a new project. Without a local shell, it uses your home directory. Project uses the root shown in Files and Git (the nearest repository or foreground checkout); outside a repository it uses the current directory. Home always uses your account home. The same policy applies to the first Quick Terminal and each fresh Quick Terminal workspace.

An explicit directory from Finder, the CLI, a workspace template, a worktree, a restored session, a project pin, or a sidebar group takes precedence. Splits keep their source pane's directory. SSH and shared remote sessions keep the directory on their remote host. Changing this setting leaves open terminals and reusable Quick Terminal workspaces running.

### `terminal.custom-directory` [#terminalcustom-directory]

string — default `""`

For the custom policy, enter an absolute path or `~/folder`, or choose a folder in Settings. Zshell checks that the folder exists and can be entered. A missing, inaccessible, or invalid custom folder falls back to the current local directory (home when none is available); Settings shows the reason. The saved path is retained while you use another policy.

### `terminal.term`

Choose **Settings → Terminal → TERM** to set `terminal.term` (default `"xterm-256color"`). The name must contain 1–128 ASCII letters, digits, or `.-_+`. Use a terminfo name installed on the machine running the shell. Changes apply to new local and SSH sessions only; open and preserved PTYs keep their original `TERM`. Shared remote sessions use the value when created with an updated server; older servers keep `xterm-256color`. An invalid value at startup falls back to `xterm-256color`; invalid edits while Zshell is running retain the last valid value. Both show an error in Settings. This setting leaves `TERM_PROGRAM` and `ZSHELL_TERM` unchanged.

### `terminal.prompt-queue-enabled` / `terminal.prompt-queue-auto-dispatch`

booleans — defaults `true` / `false`

**Settings → Terminal → Prompt Queue** controls the [per-terminal prompt queue](/en/docs/terminal#prompt-queue).
`terminal.prompt-queue-enabled = false` hides queue bars in every workspace and the
Quick Terminal, cancels pending sends, and preserves the queued entries and input
until their terminal closes. Re-enabling does not replay them.

`terminal.prompt-queue-auto-dispatch = true` opts into sending the next entry after
a command finishes. Automatic and manual sends require an empty prompt in the
original zsh shell, with no active command task. Other shells, nested shells,
foreground programs, and existing prompt drafts cannot receive queued sends.
Turning automatic sending off cancels pending sends. Enabling it takes effect on
the next command finish, without immediately replaying an existing queue.

### `terminal.backend`

`"libghostty"` · `"alacritty"` — default `"libghostty"`

Chooses the emulator used by terminals created from then on. Existing panes
keep the backend they started with. Both choices are native, GPU-accelerated,
support image rendering, and use the same Zshell themes; Alacritty generally has
the lower memory footprint.

See [Terminal backends](/en/docs/terminal#terminal-backends) for the environment
variables and compatibility contract.

### `terminal.mouse-scroll-multiplier` / `terminal.trackpad-scroll-multiplier` [#terminal-scroll-multipliers]

number, 0.1–10 — default `1` for each device

Choose **Settings → Terminal → Scrolling → Mouse wheel / Trackpad** to adjust the two speeds independently. The readouts are percentages: 100% keeps the current speed, 50% halves it, and 200% doubles it. Changes apply immediately to open Ghostty and Alacritty panes, including scrollback, full-screen programs, and mouse reporting. Momentum follows the trackpad value; horizontal scrolling stays horizontal. Precise scrolling devices use the trackpad value, including mice that report precise deltas. Missing or invalid values restore `1`; importing, exporting, and resetting settings include both values.

### `terminal.macos-option-as-alt`

boolean — default `false`

When true, Option-key combinations are sent to terminal programs as Alt/Meta
shortcuts. The default leaves Option with the active macOS input source so
layouts such as Polish Pro can type their composed characters.

### `terminal.bell`

boolean — default `true`

Controls the alert sound and macOS visual attention when a terminal program
rings the bell. When false, Zshell does not play the sound, post a terminal bell
notification, or request attention in the Dock. Accessibility technologies
still receive the bell as a semantic announcement. Both terminal backends honor
this setting.

### `terminal.vim-command-hints`

boolean — default `true`

Show mode-aware Vim / Neovim commands below the session information in the
**Info** sidebar. Applies immediately on both terminal backends, including
recognizable editors over SSH. See [Vim command hints](/en/docs/terminal#vim-command-hints)
for mode detection requirements.

### `terminal.restore-history`

boolean — default `true`

Restores each terminal's previous scrollback above a fresh shell after a
relaunch. The restored content is static text, not a surviving process.

Restored scrollback is stored on disk, so any secrets shown in the terminal may
be included.
[Projects, tabs, and pane layout](/en/docs/projects#what-survives-a-relaunch) are
restored either way.

## Automation

### `ai.enabled`

boolean — default `true`

Lets supported coding agents coordinate background Zshell panes when you ask in
plain language, and shows provider-reported lifecycle status in the UI. Zshell
does not infer status from terminal text. The Settings toggle is the recommended
way to change it because errors are shown inline and conflicting existing setups
are left untouched.

The human workflow is described in
[Working with AI agents](/en/docs/automation).

For shared Codex app-server sessions, Zshell matches verified conversation IDs to the foreground pane. Ambiguous matches remain unbound. Its managed integration adds `session-id` to Codex’s terminal title while preserving other title items.

### `ai.resume-conversations`

boolean — default `true`

When terminal panes are restored, resumes the exact recorded Claude Code, Codex, Pi, or OpenCode conversation after its original PTY is unavailable. Requires `ai.enabled = true`. A pane without a verified conversation opens a new shell; Zshell never chooses the latest conversation by directory.

Control it with **Settings → Automation → Resume agent conversations**. This setting is independent of `terminal.restore-history`.

### `ai.usage-enabled`

boolean — default `false`

Enable local CLI account-limit reading in **Settings → Automation → Account Usage → Read account usage**. Turning it off cancels pending usage requests, hides usage data, and rejects Claude usage reports without saving them. Provider choices are retained. Usage settings do not change agent recognition, lifecycle reports, or conversation restoration.

### `ai.claude-usage-enabled` / `ai.codex-usage-enabled`

boolean — default `true` for each

Choose which providers can read usage while `ai.usage-enabled = true`. Claude Code reads Zshell’s local status-line usage report; Codex queries its installed, signed-in CLI. Disabling a provider immediately stops its reads and hides its data. No sign-in credentials are collected. The three choices support settings search, import/export, live configuration reload, and reset to defaults.

## Backup and migration

Use **Zshell → Export Settings…** to save a TOML file, and **Import Settings…** to load it.
Import asks you to confirm replacement and attempts to back up the current file as `config.toml.bak` in the same directory.

Import reads every supported configuration key. Omitted keys use the configuration reader’s defaults; omitting `ai.enabled` preserves the current AI setting. Language and project or tab environment variables are stored separately.

## A complete example

```toml title="~/.config/zshell/config.toml"
theme = "dark"
theme-dark = "Catppuccin Mocha"
theme-light = "Catppuccin Latte"
font-family = "IBM Plex Mono"
font-size = 14
interface.scale = 1.25
sidebar.font-size = 13
toolbar.visibility = "auto"
terminal.font-fallback-family = "PingFang SC"
terminal.font-ligatures = true
terminal.font-features = "ss01, zero=1"
terminal.font-thicken = true
terminal.font-thicken-strength = 180
terminal.cell-width = 1.1
terminal.line-height = 1.15
terminal.mouse-scroll-multiplier = 1
terminal.trackpad-scroll-multiplier = 1
terminal.macos-option-as-alt = false
terminal.bell = false
terminal.startup-program = "/opt/homebrew/bin/fish"
terminal.startup-arguments = "--no-config"
terminal.backend = "alacritty"
terminal.restore-history = true
editor.wrap-lines = true
editor.diff-wrap-lines = false
ai.enabled = true
ai.resume-conversations = true
```

Every key is optional. Delete a key to return that setting to its default.

## Keyboard shortcuts

Open **Settings → Shortcuts** to record a new shortcut for a core command.
Zshell rejects conflicting combinations and names the command already using
them. **Restore Default Shortcuts** resets all overrides. The
[keyboard reference](/en/docs/shortcuts) lists the shipped defaults.

## Settings outside this file

- **Language.** Settings offers System Default and 17 languages, matching the
  website. Changes apply immediately while terminal sessions keep running.
  The choice uses macOS's per-app language preference, so it lives in Zshell's
  preferences rather than TOML. System Default follows the macOS language order.
- **Automatic updates.** The automatic check, download, and installation
  switches in **Settings → Updates** use app preferences outside TOML and
  remember your choices across launches. Download controls appear only while automatic checks are enabled and automatic updates are available; installation also requires automatic downloads to be enabled. See [Installation](/en/docs/installation#updates).
- **Window and layout state.** Window size, sidebar widths, selected panels,
  projects, tabs, panes, browser URLs, and diff control preferences live in
  Zshell's macOS preferences and session snapshot.
- **Backend config files.** Zshell does not read `~/.config/ghostty` or an
  Alacritty config. Zshell's settings are the supported surface for both.
