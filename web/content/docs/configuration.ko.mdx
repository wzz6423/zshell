---

대부분의 Zshell 영구 설정은 한 파일에 저장됩니다.

```
~/.config/zshell/config.toml
```

설정 창(<kbd>Cmd</kbd>+<kbd>,</kbd>)도 같은 파일에 씁니다. 언어와 자동 업데이트처럼 macOS가 관리하는 일부 설정은 다른 곳에 저장되며 이 페이지 끝에 정리되어 있습니다.

새 설정에서는 Vim 명령 힌트, 세션 기록 복원, 실패한 명령 알림이 기본적으로 켜집니다. 업데이트 자동 다운로드도 기본적으로 켜집니다. 기존 설정과 저장한 선택은 유지됩니다.

**설정 → 터미널**에서 입력 동작은 **입력**, 명령 기록과 기록 접근은 **기록**, 명령 알림과 알림 기록은 **알림**에 있습니다. **커서**와 **배경**은 **설정 → 외관**에 있습니다.

상위 기능을 끄면 종속 설정이 숨겨지고 저장한 값은 유지됩니다. 빠른 터미널 설정, 에이전트 재개와 알림, 글꼴 굵기 강도, 포커스 링 불투명도, Git 프록시 주소, 브라우저 필터 목록과 상태가 이에 해당합니다. 배경 흐림은 배경이 반투명하고 macOS의 투명도 감소가 꺼져 있을 때만 표시됩니다.

## 설정 파일의 동작 [#how-the-file-behaves]

직접 편집하기 전에 다음을 알아두세요.

- **실행 중 변경도 읽습니다.** 유효한 외부 편집은 자동 적용됩니다. 새 터미널에만 적용되는 설정은 새 창구가 필요합니다. 읽을 수 없거나 문법이 잘못된 편집은 마지막 유효 설정을 유지하며, 의도적으로 비운 파일은 잠시 후 기본값을 복원합니다.
- **파일에 저장되는 설정이 바뀔 때마다 Zshell이 다시 씁니다.** 파일 전체를 다시 생성하므로 해당 컨트롤을 다음에 사용하면 주석과 알 수 없는 키가 사라집니다. 파일을 관리할 편집 방식을 하나로 정하거나 dotfile에 기준 복사본을 보관하세요.
- **대부분의 기본값은 생략합니다.** `font-size`, `terminal.vim-command-hints`, `terminal.restore-history`, `terminal.notify-on-error`, `terminal.prompt-queue-enabled`, `terminal.prompt-queue-auto-dispatch`는 항상 저장합니다. 기존 파일에서 `terminal.vim-command-hints`, `terminal.restore-history`, `terminal.notify-on-error` 중 하나를 삭제하면 해당 기능이 꺼집니다. `terminal.prompt-queue-enabled`를 삭제하면 기본값 `true`로, `terminal.prompt-queue-auto-dispatch`를 삭제하면 기본값 `false`로 돌아갑니다. 다른 키를 삭제해도 각각의 기본값으로 돌아갑니다.
- **파서는 의도적으로 간단합니다.** 단순 키, 점으로 구분한 키, `[table]` 머리글, `#` 주석과 문자열/숫자/불리언 값을 지원합니다. 배열, 인라인 테이블과 여러 줄 문자열은 지원하지 않습니다.
- **잘못된 값은 안전한 기본값으로 대체됩니다.** 범위를 벗어난 크기, 알 수 없는 백엔드나 오타가 있는 테마 때문에 Zshell을 시작하지 못하는 일은 없습니다.

설정 저장은 파일과 디렉터리의 심볼릭 링크를 유지하고 대상 파일을 권한을 보존해 원자적으로 갱신합니다. 외부 편집은 주석이나 알 수 없는 키를 다시 쓰지 않지만, 이후 설정 창에서 저장하면 위 설명대로 파일을 재생성합니다.

## 앱 표시 위치 [#application-presence]

### `app-presence`

`"dock"` · `"dock-and-menu-bar"` · `"menu-bar"` — 기본값 `"dock"`

**설정 → 일반 → Zshell 표시 위치**에서 바꾸면 즉시 적용됩니다. `"dock"`은 Dock에만, `"dock-and-menu-bar"`는 Dock과 메뉴 막대에, `"menu-bar"`는 메뉴 막대에만 아이콘을 표시합니다.

메뉴 막대에서 현재 작업 공간, 빠른 터미널, 설정, 업데이트 확인을 열 수 있습니다. 두 메뉴 막대 모드에서는 마지막 작업 공간 윈도우를 닫아도 숨겨질 뿐 터미널과 작업이 계속 실행됩니다. **작업 공간 열기**를 선택하면 같은 윈도우, 프로젝트, 세션으로 돌아갑니다. 다른 작업 공간 윈도우, 패널, 프로젝트를 닫으면 해당 작업은 종료됩니다. 명시적 **종료**는 계속 `terminal.preserve-sessions`를 따르며, **종료하고 모든 세션 끝내기**는 작업을 종료합니다. 모드는 다시 실행해도 유지됩니다.

## 컴퓨터 잠자기 방지 [#keep-computer-awake]

### `keep-awake`

`"off"` · `"on"` · `"agents"` — 기본값 `"off"`

**설정 → 일반 → 컴퓨터 잠자기 방지** 또는 **Zshell → 컴퓨터 잠자기 방지**에서 선택합니다. `"off"`는 자동 잠자기를 허용하고 `"on"`은 Zshell이 실행 중일 때 시스템의 자동 잠자기를 방지합니다. `"agents"`는 로컬 에이전트가 작업할 때만 방지합니다.

`"agents"` 모드에서는 백그라운드 프로젝트, 다른 창, 숨겨지거나 확대된 분할 창을 포함하여 모든 로컬 터미널 창을 확인합니다. 원격 에이전트는 포함하지 않습니다. 다른 로컬 에이전트가 작업하지 않으면 대기, 유휴, 완료 상태에서 잠자기를 허용하며, 마지막 작업 창을 닫으면 잠자기 방지가 해제됩니다. `"on"` 모드는 Zshell이 실행되는 동안 자동 잠자기를 계속 방지합니다. 모든 모드에서 끄기를 선택하거나 Zshell을 종료하면 터미널 세션을 보존하더라도 잠자기 방지가 해제됩니다.

설정 행은 방지 기능의 실제 활성 상태 또는 사용 불가 상태를 표시합니다. 디스플레이 잠자기, 수동 잠자기, 덮개 닫기 및 배터리 부족 시 잠자기는 macOS 정책을 따릅니다.

## 모양 [#appearance]

### `theme` [#theme]

`"system"` · `"light"` · `"dark"` — 기본값 `"system"`

앱 모양을 선택합니다. `"system"`은 macOS를 따르고 나머지 두 값은 특정 모양으로 고정합니다.

### `theme-dark`와 `theme-light` [#theme-dark-and-theme-light]

문자열 — 기본값 `"Default Dark"` 및 `"Default Light"`

각 모양의 색상 테마입니다. 테마는 터미널 분할 창, 창 프레임, 사이드바, 편집기와 차이 보기의 색상을 함께 바꿉니다. 기본 내장 테마는 반투명 사이드바를 유지하고 다른 테마는 각 색상표에 맞게 사이드바를 칠합니다.

설정에는 두 터미널 백엔드가 공유하는 선별된 테마 목록이 표시됩니다. 파일에 직접 적는 이름은 대소문자까지 표시 이름과 정확히 일치해야 합니다. 그렇지 않으면 해당 모양의 기본 테마로 돌아갑니다.

### `terminal.minimum-contrast` [#terminalminimum-contrast]

`1`–`21` · `3`

**설정 → 모양 → 색상 → 최소 대비**에서 터미널 텍스트 가독성을 `1`–`21` 범위로 조정합니다(기본값 `3`). `1`은 원래 ANSI 색상을 유지합니다. 두 백엔드 모두 셸을 다시 시작하지 않고 열린 터미널과 Quick Terminal을 업데이트하며 프로필의 색상도 유지합니다. 이모지와 이미지 픽셀의 색상은 바뀌지 않습니다. 선택 영역과 커서는 각 백엔드의 기본 가독성 정책을 유지합니다. 배경에서 요청한 비율을 달성할 수 없으면 각 백엔드가 가능한 가장 읽기 쉬운 색상을 사용합니다. 투명 터미널은 해석된 셀 배경을 사용하므로 데스크톱과 합성한 최종 대비는 다를 수 있습니다.

### `toolbar.visibility` [#toolbarvisibility]

`"hide"` · `"auto"` · `"always"` — 기본값 `"hide"`

활성 탭 아래의 간결한 도구 막대를 제어합니다.

- `"hide"`는 창에서 도구 막대를 숨깁니다.
- `"auto"`는 프로젝트 디렉터리가 Git 저장소일 때만 표시합니다.
- `"always"`는 **Git 저장소 없음** 상태를 포함해 모든 프로젝트에 Git 진입점을 표시합니다.

표시되는 내용은 [Git 도구 막대](/ko/docs/git#the-git-toolbar)를 참고하세요.

## 텍스트 [#text]

### `font-family` [#font-family]

문자열 — 기본값 `""`이며 내장 JetBrains Mono를 뜻합니다.

터미널, 편집기와 차이 보기가 이 라틴 글꼴 모음을 공유합니다. 개별 스타일인 `"IBM Plex Mono Regular"`가 아니라 `"IBM Plex Mono"` 같은 글꼴 모음 이름을 지정하세요. 알 수 없거나 고정폭이 아닌 글꼴 모음은 내장 기본 글꼴로 대체됩니다.

터미널은 라틴 글꼴 모음, 아래의 선택적 CJK 대체 글꼴, 내장 Symbols Nerd Font, 백엔드의 시스템 대체 글꼴 순서로 사용합니다. 편집기와 차이 보기는 기존 macOS/WebKit 대체 글꼴 방식을 계속 사용합니다.

### `terminal.font-fallback-family` [#terminalfont-fallback-family]

문자열 — 기본값 `""`이며 백엔드/시스템 대체 글꼴을 뜻합니다.

설치된 CJK 글꼴 모음 하나를 터미널의 대체 글꼴 순서에 추가합니다. 설정 선택기에는 대표적인 중국어, 일본어 또는 한국어 글리프를 포함한 모음이 표시됩니다. 기본 라틴 글꼴에 없는 글리프만 제공하므로 엄격한 고정폭일 필요는 없습니다.

### `font-size` [#font-size]

숫자, 8–32 — 기본값 `13`

터미널, 편집기와 차이 보기가 공유하는 포인트 단위 글꼴 크기입니다. 기본값이어도 Zshell이 항상 기록하는 유일한 키입니다.

### `interface.scale` [#interfacescale]

숫자, 0.9–1.5 — 기본값 `1`

탭, 아이콘, 버튼, 사이드바와 나머지 앱 인터페이스의 배율을 조절합니다. 터미널, 편집기와 차이 보기의 내용은 위에서 따로 설정한 글꼴 크기를 유지합니다.

### `sidebar.font-size` [#sidebarfont-size]

숫자, 9–24 — 기본값 `14`

양쪽 사이드바의 기본 글자 크기입니다. 기본 크기가 바뀌어도 구역 제목, 행, 메타데이터와 컨트롤은 상대적인 계층을 유지합니다.

### `sidebar.double-click-new-session` [#sidebardouble-click-new-session]

불리언 — 기본값 `true`

사이드바의 빈 공간을 두 번 클릭하면 선택한 프로젝트에 세션을 만듭니다. 선택한 프로젝트가 없으면 프로젝트를 만듭니다. 행 클릭과 끌기는 기존 동작을 유지합니다.

### `terminal.font-ligatures` [#terminalfont-ligatures]

불리언 — 기본값 `true`

**설정 → 외관 → 글꼴 합자**에서 두 터미널 백엔드의 선택적 합자를 켜거나 끕니다. 끄면 `calt`, `liga`, `clig`, `dlig`, `hlig`를 덮어쓰지만 문자에 필수적인 조형은 유지합니다. 원래 문자, 터미널 열, 커서와 선택 영역은 그대로입니다.

### `terminal.font-features` [#terminalfont-features]

문자열 — 기본값 `""`, 글꼴 기본 기능 사용

같은 글꼴 그룹의 **OpenType 기능**에 4자 태그를 쉼표나 공백으로 구분해 입력하세요. `-calt`는 문맥 대체를 끄고, `ss01`은 스타일 집합 1, `zero=1`은 대체 숫자 0을 켭니다. `+liga`와 `liga=1`도 기능을 켭니다. 같은 태그에서는 뒤의 값이 우선합니다. 합자 스위치가 위 다섯 태그보다 우선합니다.

변경은 열린 터미널과 미리 보기에 즉시 적용됩니다. 두 백엔드 모두 선택한 글꼴이 지원하는 기능을 사용하며 미지원 태그는 효과가 없습니다. 설정의 잘못된 입력은 마지막 유효값을 유지하고, 잘못된 외부 값은 글꼴 기본값을 사용합니다. 기본값으로 재설정하면 기능 목록을 비우고 합자를 켭니다.

### `terminal.font-thicken` [#terminalfont-thicken]

불리언 — 기본값 `false`

기존 macOS 글꼴 다듬기와 비슷하게 터미널 글리프의 획을 약간 굵게 표시합니다. 두 백엔드 모두 지원하며 설정 미리보기에서 결과를 확인할 수 있습니다. 예전 `font-thicken` 설정도 읽고 이후 현재의 점 구분 키로 다시 씁니다.

### `terminal.font-thicken-strength` [#terminalfont-thicken-strength]

정수, 0–255 — 기본값 `255`

`terminal.font-thicken`이 true일 때 굵게 처리하는 정도를 조절합니다. 0은 끄기가 아니라 가장 약한 굵기 보정입니다. Ghostty는 macOS의 기본 강도를 사용하고 Alacritty는 같은 범위를 CoreText 획에 대응시킵니다. 따라서 방향과 양 끝값은 같지만 실제 래스터화된 픽셀은 다를 수 있습니다.

### `terminal.cell-width` [#terminalcell-width]

숫자, 0.75–2 — 기본값 `1`

**설정 → 모양 → 글꼴 → 셀 너비**에서 터미널 열 간격을 조절합니다. 기본값은 100%이며 정수 백분율로 저장됩니다. 두 백엔드 모두 열린 터미널에 즉시 적용하며 PTY 열 수, 커서, 선택 영역과 키보드 힌트도 갱신합니다. 글리프 크기는 유지되고 넓은 문자는 계속 두 열을 차지합니다. 픽셀 반올림 때문에 실제 조절 단계는 백엔드마다 다를 수 있습니다. 잘못된 값은 100%로 복원됩니다. 편집기와 diff 간격은 바뀌지 않습니다.

### `terminal.line-height` [#terminalline-height]

숫자, 0.75–2 — 기본값 `1`

글리프를 세로 중앙에 유지하면서 각 터미널 백엔드의 기본 셀 높이에 배율을 적용합니다. 터미널 행만 바꾸며 편집기나 차이 보기의 줄 간격은 바꾸지 않습니다.

Zshell은 기본 글꼴 두께 컨트롤을 제공하지 않습니다. Ghostty는 이름이 있는 스타일이나 가변 축을 고르고 Alacritty/CoreText는 속성으로 보통체와 굵은체를 결정합니다. 하나의 공통 값으로는 정적 및 가변 글꼴 전체에서 보통체/굵은체의 구분과 대체 글꼴 두께를 일관되게 유지할 수 없기 때문입니다.

### `terminal.padding-color` [#terminalpadding-color]

`"background"` · `"extend"` · `"always"` — `"extend"`

**설정 → 모양 → 배경 → 여백 색상**에서 선택합니다. `"background"`는 여백에 터미널 테마 배경을 사용합니다. `"extend"`는 가장 가까운 셀의 배경을 확장하지만, 첫 행이나 마지막 행에 기본 배경 셀, 셸 프롬프트 또는 Powerline 구분자가 있으면 위아래 여백은 테마 배경을 유지합니다. `"always"`는 이 검사를 건너뛰고 모든 가장자리로 확장합니다. 빈 마지막 행은 자체 배경을 유지하며, 그 위의 색상 행이 아래 여백을 채우지 않습니다. 변경은 두 백엔드의 열린 터미널에 즉시 적용됩니다. 반투명 배경에서는 기본 배경이 설정된 불투명도를 유지하고 명시적인 셀 배경과 확장 부분은 불투명하게 표시됩니다.

### `editor.wrap-lines` [#editorwrap-lines]

불리언 — 기본값 `true`

[파일 편집기](/ko/docs/files)의 긴 줄을 분할 창 너비에 맞춰 화면상으로 줄바꿈합니다. false이면 긴 줄을 가로로 스크롤합니다. 터미널이나 차이 보기의 줄바꿈은 바꾸지 않습니다.

### `editor.diff-wrap-lines` [#editordiff-wrap-lines]

불리언 — 기본값 `false`

**설정 → 편집기 → 차이 보기 너비에 맞춰 줄바꿈** 또는 차이 보기 도구 막대의 줄바꿈 버튼으로 전환합니다. 통합·분할 보기, 편집 가능한 작업 트리 변경, 과거 차이 보기 및 PR 댓글에서 긴 줄을 창 너비에 맞춰 표시합니다. 열린 모든 차이 보기에 즉시 적용되고 재시작 후에도 유지됩니다. 끄면 가로 스크롤로 돌아갑니다. 파일 편집기와 터미널 줄바꿈 설정과는 별개입니다.

### `editor.protect-saves` [#editorprotect-saves]

불리언 — 기본값 `true`

파일이나 편집 가능한 작업 트리 diff를 저장하기 전에 외부 프로그램의 변경을 확인합니다. 충돌 시 초안과 비교, 디스크에서 다시 불러오기, 초안 유지, 명시적 덮어쓰기를 선택할 수 있습니다. 끄면 충돌 확인 없이 외부 변경을 교체합니다.

### `editor.recover-drafts` [#editorrecover-drafts]

불리언 — 기본값 `true`

Zshell은 로컬 파일과 편집 가능한 작업 트리 diff의 저장하지 않은 변경을 기본으로 백업합니다. 예기치 않은 종료 후 다시 열린 창에서 초안, 선택 영역, 레이아웃을 복구합니다. 다른 백업은 **파일 → 초안 복구…** 또는 **설정 → 편집기 → 초안 복구…**에서 선택하고 내용을 확인한 뒤 **초안 복구**를 누르세요. 복구는 저장하지 않은 편집기를 열기만 하며 디스크 파일을 변경하지 않습니다. 저장할 때는 편집 전 버전을 기준으로 외부 변경을 확인합니다.

**설정 → 편집기 → 저장하지 않은 초안 백업** 또는 `editor.recover-drafts`로 제어합니다. 끄면 새 백업과 자동 복구가 중지되며 기존 백업은 수동 복구나 삭제할 수 있습니다. **백업 삭제**는 선택한 백업만 삭제하고 열린 편집 내용은 유지합니다. 저장 성공 또는 닫기 완료 시 **저장하지 않음**을 선택하면 백업이 삭제됩니다. 백업은 이 Mac의 비공개 파일에 최대 32개, 총 128 MiB로 저장되며 최대 30일 동안 보관됩니다. 용량 제한으로 오래된 백업이 더 일찍 삭제될 수 있습니다. 5 MiB를 넘는 파일이나 편집 텍스트는 제외됩니다.

Zshell은 시작 시와 실행 중 매시간 만료된 백업을 삭제하며, 백업을 꺼도 정리는 계속됩니다. Zshell이 종료된 동안 만료된 파일은 다음 실행 때 삭제될 때까지 디스크에 남습니다.

## 터미널 [#terminal]

### `terminal.startup-program` / `terminal.startup-arguments` [#terminalstartup-program--terminalstartup-arguments]

문자열 — 기본적으로 설정하지 않음

이후 생성하는 터미널의 실행 파일과 인수 목록을 선택합니다. `terminal.startup-program`이 없으면 계정의 로그인 셸을 `-l` 옵션으로 계속 사용합니다. 프로그램은 실행 가능한 파일의 절대 경로여야 합니다. 경로가 없거나 실행할 수 없으면 동작하지 않는 창을 여는 대신 로그인 셸로 돌아갑니다.

`terminal.startup-arguments`는 셸을 호출하지 않고 인수로 나눕니다. 따옴표와 역슬래시는 공백 및 빈 인수를 포함한 경계를 유지하지만 변수, glob 패턴과 명령 치환은 확장하지 않습니다. 따옴표가 잘못되어도 로그인 셸로 돌아갑니다. Zshell CLI로 명시적인 argv를 전달했다면 해당 터미널에서는 그것이 우선합니다.

### `terminal.new-session-directory` [#terminalnew-session-directory]

`"current"` · `"project"` · `"home"` · `"custom"` — 기본값 `"current"`

**설정 → 터미널 → 새 세션 디렉터리**에서 선택합니다. 현재 디렉터리는 활성 로컬 셸의 위치를 사용하며 새 프로젝트의 첫 터미널도 이를 상속합니다. 로컬 셸이 없으면 홈을 사용합니다. 프로젝트는 파일과 Git 패널에 표시되는 루트(가장 가까운 저장소 또는 포그라운드 체크아웃)를 사용하고 저장소 밖에서는 현재 디렉터리를 사용합니다. 홈은 항상 계정의 홈을 사용합니다. 첫 빠른 터미널과 매번 새로 만드는 빠른 터미널 작업 공간에도 같은 정책이 적용됩니다.

Finder, CLI, 작업 공간 템플릿, worktree, 복원된 세션, 프로젝트 고정 디렉터리 또는 사이드바 그룹에서 명시한 경로가 우선합니다. 분할은 원본 창의 디렉터리를 유지합니다. SSH와 공유 원격 세션은 원격 호스트의 디렉터리를 유지합니다. 설정을 바꿔도 열린 터미널과 재사용하는 빠른 터미널 작업 공간은 계속 실행됩니다.

### `terminal.custom-directory` [#terminalcustom-directory]

문자열 — 기본값 `""`

사용자 지정 정책에서는 절대 경로나 `~/folder`를 입력하거나 설정에서 폴더를 선택합니다. Zshell은 폴더가 존재하고 진입할 수 있는지 확인합니다. 폴더가 없거나 접근할 수 없거나 경로가 잘못되면 현재 로컬 디렉터리(없으면 홈)로 돌아가며 설정에 이유를 표시합니다. 다른 정책을 선택해도 저장한 경로는 유지됩니다.

### `terminal.term`

**설정 → 터미널 → TERM**에서 `terminal.term`을 설정하세요(기본값 `"xterm-256color"`). 이름은 1–128자의 ASCII 문자, 숫자 또는 `.-_+`로 구성되어야 합니다. shell을 실행하는 호스트에 설치된 terminfo 이름을 사용하세요. 변경은 새 로컬 및 SSH 세션에만 적용되며 열린 PTY와 유지된 PTY는 기존 `TERM`을 유지합니다. 공유 원격 세션은 업데이트된 서버에서 생성될 때 이 값을 사용하며 이전 서버는 `xterm-256color`를 유지합니다. 시작 시 값이 잘못되면 `xterm-256color`로 대체하고, Zshell 실행 중 잘못된 편집은 마지막 유효 값을 유지합니다. 두 경우 모두 설정에 오류를 표시합니다. `TERM_PROGRAM`과 `ZSHELL_TERM`은 변경되지 않습니다.

### `terminal.backend` [#terminalbackend]

`"libghostty"` · `"alacritty"` — 기본값 `"libghostty"`

이후 만드는 터미널의 에뮬레이터를 선택합니다. 기존 분할 창은 시작할 때 사용한 백엔드를 유지합니다. 둘 다 네이티브 GPU 가속, 이미지 렌더링과 같은 Zshell 테마를 지원하며 Alacritty는 일반적으로 메모리를 더 적게 사용합니다.

환경 변수와 호환성 규약은 [터미널 백엔드](/ko/docs/terminal#terminal-backends)를 참고하세요.

### `terminal.mouse-scroll-multiplier` / `terminal.trackpad-scroll-multiplier` [#terminal-scroll-multipliers]

숫자, 0.1–10 — 각 장치의 기본값 `1`

**설정 → 터미널 → 스크롤 → 마우스 휠 / 트랙패드**에서 두 속도를 따로 조절합니다. 표시는 백분율입니다. 100%는 현재 속도, 50%는 절반, 200%는 두 배입니다. 변경은 열린 Ghostty 및 Alacritty 패널의 스크롤백, 전체 화면 프로그램, 마우스 보고에 즉시 적용됩니다. 관성 스크롤은 트랙패드 값을 따르며 가로 스크롤은 가로 방향을 유지합니다. 정밀 스크롤 델타를 보고하는 마우스도 트랙패드 값을 사용합니다. 누락되거나 잘못된 값은 `1`로 돌아가며 설정 가져오기, 내보내기, 초기화에 두 값이 모두 포함됩니다.

### `terminal.macos-option-as-alt` [#terminalmacos-option-as-alt]

불리언 — 기본값 `false`

true이면 Option 키 조합을 Alt/Meta 단축키로 터미널 프로그램에 보냅니다. 기본값에서는 Option을 활성 macOS 입력 소스에 맡기므로 Polish Pro 같은 배열에서 조합 문자를 입력할 수 있습니다.

### `terminal.bell` [#terminalbell]

터미널 프로그램이 벨을 울릴 때 경고음과 macOS 시각적 주의 알림을 제어합니다. false이면 소리를 내거나 터미널 벨 알림을 게시하거나 Dock에서 주의를 요청하지 않습니다. 보조 기술에는 여전히 벨의 의미를 알리는 접근성 알림을 전달합니다. 두 백엔드 모두 이 설정을 따릅니다.

### `terminal.vim-command-hints` [#terminalvim-command-hints]

**정보** 사이드바의 세션 정보 아래에 모드에 맞는 Vim / Neovim 명령을 표시합니다. 두 백엔드에 즉시 적용되며 SSH를 통해 인식할 수 있는 편집기도 포함됩니다. 모드 감지 조건은 [Vim 명령 힌트](/ko/docs/terminal#vim-command-hints)를 참고하세요.

### `terminal.restore-history` [#terminalrestore-history]

불리언 — 기본값 `true`

재실행 후 새 셸 위에 각 터미널의 이전 스크롤 기록을 복원합니다. 복원 내용은 살아 있는 프로세스가 아닌 정적인 텍스트입니다.

복원용 스크롤 기록은 디스크에 저장되므로 터미널에 표시된 비밀 정보가 포함될 수 있습니다. 이 설정과 관계없이 [프로젝트, 탭과 분할 창 배치](/ko/docs/projects#what-survives-a-relaunch)는 복원됩니다.

## 브라우저 접근 [#browser-access]

이전 Zshell 버전이 보존한 세션이 실행 중이면 브라우저 접근은 모든 세션을 종료하고 앱을 다시 열도록 안내합니다. 사용자가 선택하기 전까지 기존 작업은 유지됩니다.

### `browser-access.enabled`

`browser-access.enabled`는 불리언이며 기본값은 `false`입니다. **설정 → 브라우저 접근**에서 활성화하면 새로 연 로컬 터미널 패널을 사용할 수 있습니다. 기존 패널은 현재 프로세스를 유지합니다. 두 백엔드 모두 지원하며 `terminal.preserve-sessions`를 바꾸지 않습니다.

### `browser-access.interface` / `browser-access.port`

`browser-access.interface` 기본값은 `"loopback"`(**로컬호스트만**)입니다. 다른 기기에서 연결하려면 사용 가능한 사설 IPv4 LAN 또는 Tailscale 인터페이스를 명시적으로 선택하세요. 저장 값에는 정확한 이름과 주소(예: `"en0|192.168.0.10"`)가 포함됩니다. `browser-access.port`는 HTTPS 포트이며 범위는 1024–65535, 기본값은 `7443`입니다. 로컬 페이지는 별도의 로컬 전용 HTTP 주소를 사용합니다. 인터페이스를 사용할 수 없으면 다시 선택해야 하며 모든 인터페이스로 수신 범위를 넓히지 않습니다.

로컬 HTTP 페이지는 보통 설정한 HTTPS 포트의 다음 포트(기본값 `7444`)를 사용합니다. 포트 사용 상태가 바뀌지 않으면 잠자기 해제, 재시도, 다시 열기 후에도 주소와 승인이 유지됩니다. 포트가 사용 중이면 다음 7개 로컬 포트를 순서대로 시도하며 `65535` 다음은 `1024`입니다. 포트 사용 상태가 바뀌면 다시 시작할 때 다른 주소가 선택될 수 있습니다. 기존 승인은 이전 출처에 연결되어 있으므로 새 주소에서는 다시 페어링해야 합니다. 접근이 꺼져 있어도 저장된 클라이언트를 확인하고 취소할 수 있습니다. 32개 한도에 도달하면 새 클라이언트를 승인하기 전에 기존 승인을 취소하세요. 세션 서비스를 확인할 수 없어도 접근은 켜진 상태로 유지됩니다. 서비스가 준비되면 재시도를 클릭하세요.

원격 페어링 전에 TLS 인증서 지문을 비교하고 클라이언트에서 내보낸 인증서를 신뢰하세요. Mac에서 클라이언트를 승인하거나 취소할 수 있습니다. 비활성화, 잠자기, 앱 종료 시 브라우저 연결이 닫히며 앱 종료는 기존 세션 보존 설정을 따릅니다. [브라우저에서 이 Mac에 접근하기](/ko/docs/remote-sessions#browser-access)를 참고하세요.

## 자동화 [#automation]

### `ai.enabled` [#aienabled]

불리언 — 기본값 `true`

평소 말하듯 요청하면 지원하는 코딩 에이전트가 백그라운드 Zshell 분할 창을 조율하고 제공자가 보고한 수명 주기 상태를 UI에 표시할 수 있습니다. 오류를 인라인으로 보여 주고 충돌하는 기존 설정은 건드리지 않으므로 설정 창의 스위치로 변경하는 것이 좋습니다.

실제 사용 흐름은 [AI 에이전트와 작업](/ko/docs/automation)에서 설명합니다.

Codex app-server를 공유할 때 검증된 대화 ID를 전경 창에 연결하며, 모호한 경우 연결하지 않습니다. 관리되는 통합은 다른 제목 항목을 유지하면서 Codex 터미널 제목에 `session-id`를 추가합니다.

### `ai.resume-conversations` [#airesume-conversations]

불리언 — 기본값 `true`

터미널 창 복원 시 원래 PTY를 사용할 수 없으면 기록된 Claude Code, Codex, Pi 또는 OpenCode의 정확한 원래 대화를 재개합니다. `ai.enabled = true`가 필요합니다. 확인된 대화가 없는 창은 새 셸을 열며, Zshell은 디렉터리를 기준으로 최근 대화를 선택하지 않습니다.

**설정 → 자동화 → 에이전트 대화 재개**에서 전환합니다. `terminal.restore-history`와 독립적인 설정입니다.

### `ai.usage-enabled`

불리언 — 기본값 `false`

**설정 → 자동화 → 계정 사용량 → 계정 사용량 읽기**에서 로컬 CLI 계정 한도 읽기를 켭니다. 끄면 대기 중인 사용량 요청을 취소하고 데이터를 숨기며 Claude 사용량 보고서 저장을 거부합니다. 공급자 선택은 유지됩니다. 에이전트 인식, 수명 주기 보고 및 대화 복원은 변경하지 않습니다.

### `ai.claude-usage-enabled` / `ai.codex-usage-enabled`

불리언 — 각각 기본값 `true`

`ai.usage-enabled = true`일 때 사용량을 읽을 공급자를 선택합니다. Claude Code는 Zshell의 로컬 상태 표시줄 보고서를 읽고 Codex는 설치되고 로그인된 CLI를 조회합니다. 공급자를 끄면 즉시 읽기를 중지하고 데이터를 숨깁니다. 로그인 자격 증명은 수집하지 않습니다. 세 설정 모두 검색, 가져오기/내보내기, 실시간 설정 다시 로드 및 기본값 복원을 지원합니다.

## 백업과 마이그레이션 [#backup-and-migration]

<strong>Zshell → 설정 내보내기…</strong>로 TOML 파일을 저장하고 <strong>설정 가져오기…</strong>로 불러옵니다. 가져오기 전에 교체 여부를 확인하며 현재 파일을 같은 디렉터리의 `config.toml.bak`로 백업하려고 시도합니다.

가져오기는 지원되는 모든 설정을 읽습니다. 생략한 키는 설정 판독기의 기본값을 사용하며, `ai.enabled`를 생략하면 현재 AI 설정을 유지합니다. 언어와 프로젝트 또는 탭의 환경 변수는 별도로 저장됩니다.

theme-light = "Catppuccin Latte"

## 키보드 단축키 [#keyboard-shortcuts]

**설정 → 단축키**에서 주요 명령의 새 단축키를 지정하세요. Zshell은 충돌하는 조합을 거부하고 이미 사용하는 명령의 이름을 알려 줍니다. **기본 단축키 복원**은 모든 재정의를 초기화합니다. [단축키 안내](/ko/docs/shortcuts)에 기본값이 정리되어 있습니다.

## 이 파일 밖의 설정 [#settings-outside-this-file]

- **언어.** 설정에는 시스템 기본값과 웹사이트와 동일한 17개 언어가 있습니다. 터미널 세션을 계속 실행하는 상태에서 변경이 즉시 적용됩니다. macOS의 앱별 언어 환경설정을 사용하므로 TOML이 아닌 Zshell 환경설정에 저장됩니다. 시스템 기본값은 macOS의 언어 우선순위를 따릅니다.
- **자동 업데이트.** **설정 → 업데이트**의 자동 확인, 다운로드와 설치 스위치는 TOML 밖의 앱 환경설정에 저장되며 재실행 후에도 유지됩니다. 자동 확인이 켜져 있고 자동 업데이트를 사용할 수 있을 때 다운로드 설정을 표시합니다. 설치 설정은 자동 다운로드도 켜져 있어야 표시됩니다. [설치](/ko/docs/installation#updates)를 참고하세요.
- **창과 배치 상태.** 창 크기, 사이드바 너비, 선택한 패널, 프로젝트, 탭, 분할 창, 브라우저 URL과 차이 보기 컨트롤 설정은 Zshell의 macOS 환경설정과 세션 스냅샷에 저장됩니다.
- **백엔드 설정 파일.** Zshell은 `~/.config/ghostty`나 Alacritty 설정을 읽지 않습니다. 두 백엔드 모두 Zshell 자체 설정을 사용해야 합니다.


## Agent 인식 규칙 [#agent-recognition-rules]

`ai.custom-recognition-rules` · `ai.screen-inference` — `true` / `false`, 기본값 `true`

**설정 → AI → Agent 인식** 또는 **Agents → Agent 규칙 관리…**에서 로컬 규칙을 추가, 편집, 삭제, 가져오기, 내보내기, 초기화할 수 있습니다. 사용자 정의 인식과 화면 상태 추론은 독립된 스위치이며 기본값은 둘 다 켜짐입니다. 끄면 기존 화면 증거가 즉시 제거됩니다. 기본 수명 주기 이벤트와 프로그램 보고가 우선합니다.
