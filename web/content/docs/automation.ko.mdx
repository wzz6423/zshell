---

Zshell 자동화는 주로 AI 코딩 에이전트를 위한 기능입니다. 에이전트가 Zshell 분할 창을 다루고 다른 에이전트와 협업할 수 있는 안전한 인터페이스를 제공하며, 사용자가 별도의 명령 언어를 배울 필요는 없습니다.

AI 통합은 기본적으로 켜져 있습니다. 평소처럼 코딩 에이전트에게 요청하세요. 에이전트는 사용 중인 분할 창의 포커스를 빼앗지 않고 백그라운드 창 생성, 작업 에이전트 실행, 명령 실행, 결과 대기와 응답 전달을 수행할 수 있습니다.

## 설정 [#setup]

**설정 → 자동화 → AI**를 확인하세요. 기본적으로 켜져 있지만 전에 껐다면 다시 켠 다음 새 터미널을 열거나 이미 실행 중이던 에이전트를 재시작하세요.

Zshell은 Codex, Claude Code, Gemini CLI, Grok Build, OpenCode, Cursor Agent, Aider, Amp 및 Pi를 지원합니다. 이 기능과 충돌하는 기존 에이전트 설정을 발견하면 해당 설정을 건드리지 않고 스위치를 이전 상태로 되돌린 뒤 설정 화면에 오류를 표시합니다.

## 평소 말하듯 요청하기 [#ask-in-plain-language]

원하는 결과를 에이전트에게 말하세요. 예를 들면 다음과 같습니다.

> 관련 테스트를 백그라운드 분할 창에서 실행하고 실패한 항목을 알려 줘.

> 이 버그를 다른 Codex 에이전트에게 맡긴 다음 결과를 검토해 줘.

> API 작업 중인 에이전트에게 스키마가 준비됐는지 물어보고, 답을 테스트 중인 에이전트에게 전달해 줘.

> 옆에서 개발 서버를 시작하고 준비될 때까지 기다린 다음 URL을 알려 줘.

> 백그라운드 에이전트가 작업을 마쳤는지 확인해 줘. 막혀 있다면 무엇이 필요한지 알려 줘.

에이전트가 Zshell 자동화 인터페이스를 대신 다룹니다. 사용자가 Zshell 자동화 명령을 입력하거나 외울 필요가 없습니다.

## 분할 창 간 에이전트 협업 [#let-agents-coordinate-across-panes]

관련 작업을 여러 Zshell 분할 창에 나누고 주 에이전트에게 조율을 맡길 수 있습니다. 예를 들어 한 에이전트는 API를 만들고 다른 에이전트는 테스트를 갱신합니다. 조율 에이전트는 특정 작업자에게 조사 결과를 요청하고, 후속 요청을 보내며, 유용한 결과를 다른 작업자에게 전달한 다음 종합한 답을 사용자에게 돌려줍니다. 작업자들은 서로 다른 지원 코딩 도구를 사용할 수도 있습니다.

병렬 작업에서 맥락을 복사해 붙여넣는 단계를 줄일 수 있습니다. 각 에이전트는 자기 분할 창에서 대화를 유지하고, 조율 에이전트는 다른 작업자에게 필요한 질문, 갱신 내용이나 결과만 전달합니다.

후속 요청을 보냈다고 작업이 끝난 것은 아닙니다. 조율 에이전트는 작업자를 기다리고 결과를 읽은 뒤 성과를 확인합니다. 다른 에이전트의 메시지도 사용자의 승인으로 취급하지 않습니다. 권한, 자격 증명, 신뢰 여부와 파괴적인 작업의 결정권은 여전히 사용자에게 있습니다.

## 실행 중에도 계속 작업하기 [#keep-working-while-it-runs]

위임된 분할 창은 표시해 달라고 요청하지 않는 한 백그라운드에 머뭅니다. 제공자의 기본 수명 주기 통합이 상태를 보고하면 Zshell은 에이전트의 창과 탭에 표시합니다.

| 상태 | 의미 |
| --- | --- |
| **작업 중** | 에이전트가 작업을 수행하고 있습니다. |
| **차단됨** | 사용자의 입력, 승인 또는 다른 결정이 필요합니다. |
| **완료** | 백그라운드에서 작업을 마쳤고 아직 해당 창을 확인하지 않았습니다. |

Zshell은 전송한 프롬프트를 **작업 중**으로 기록하지만 이후 상황을 추측하기 위해 렌더링된 터미널 텍스트를 검사하지는 않습니다. **차단됨** 및 **완료** 전환과 알림에는 제공자의 수명 주기 보고가 필요합니다. 보고하지 않는 에이전트라면 추측한 상태에 의존하지 말고 해당 분할 창과 프로젝트 변경을 직접 확인하세요.

통합 기능이 에이전트의 완료나 입력 필요 상태를 보고하면 Zshell이 알림도 보낼 수 있습니다. <kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>A</kbd>로 보고된 에이전트 중 확인이 필요한 다음 항목으로 이동하세요.

## 계정 사용량과 한도 [#account-usage-and-limits]

**설정 → 자동화 → 계정 사용량**은 Claude Code와 Codex에서 제공하는 계정 한도를 보여 줍니다. 사용 비율, 보고된 경우 초기화 시각, 마지막 갱신 시각을 포함합니다. **사용량 새로 고침**으로 최신 데이터를 다시 불러오세요.

Codex는 계정 한도를 보고할 수 있는 CLI가 설치되어 있고 로그인되어 있어야 합니다. Claude Code 사용량은 Zshell이 제공자의 상태 표시줄 사용량 보고를 받았을 때 표시됩니다. 데이터가 있을 때만 이 구역이 나타나며 지원하는 시간 구간은 제공자와 계정에 따라 달라집니다. 표시되는 값은 계정 한도이며 포커스된 세션의 토큰 총량이 아닙니다.

## 일반적인 작업 순서 [#a-typical-workflow]

1. Zshell 터미널에서 평소 사용하는 코딩 에이전트를 시작합니다.
2. 범위가 정해진 작업을 위임하거나 백그라운드에서 실행하거나 다른 에이전트와 조율해 달라고 요청합니다.
3. Zshell이 프로젝트 배치에 위임된 작업을 표시하는 동안 현재 분할 창에서 작업을 계속합니다.
4. 제공자가 보고하는 **작업 중**, **차단됨** 또는 **완료** 배지가 있다면 확인합니다. 도구가 수명 주기를 보고하지 않으면 창을 열어 대화나 터미널 출력을 직접 확인합니다.
5. 결과 파일을 [Git 패널](/ko/docs/git)에서 검토하고 차이를 확인한 뒤 남길 내용을 결정합니다.

## 결정권은 사용자에게 [#you-stay-in-control]

- 에이전트 자동화는 현재 Zshell 프로젝트 안에 한정되며 다른 프로젝트나 창의 분할 창에 접근할 수 없습니다.
- 명시적으로 요청하지 않는 한 백그라운드 작업이 포커스를 가져가지 않습니다.
- Zshell은 권한, 자격 증명, 신뢰 여부나 파괴적인 작업 확인에 대신 응답하지 않습니다. 제공자가 차단 상태를 보고하면 결정을 사용자에게 돌려줍니다.
- 완료 보고는 결과를 검토하라는 신호이며, 에이전트의 변경을 자동 승인한다는 뜻이 아닙니다.

## 에이전트가 Zshell을 사용하지 않는 경우 [#if-an-agent-does-not-use-zshell]

- **설정 → 자동화 → AI**가 켜져 있는지 확인하세요.
- 현재 터미널이 설정을 켜기 전부터 열려 있었다면 새 Zshell 터미널을 여세요.
- 설정을 켤 때 이미 실행 중이던 에이전트를 재시작하세요.
- 설정 화면에 인라인 설정 오류가 있는지 확인하세요.
- 이 작업 방식을 사용하게 하려면 명확히 “백그라운드 Zshell 분할 창”이나 “위임된 Zshell 에이전트”를 요청하세요.
