---
title: 원격 세션 공유
description: SSH 또는 Tailscale로 같은 원격 터미널에 연결하고 연결이 끊겨도 작업을 유지합니다.
---

`zshell-server`가 macOS 또는 Linux 호스트에서 셸과 작업을 유지합니다. Zshell의 두 터미널 백엔드에서 사용할 수 있으며 클라이언트를 닫거나 종료해도 작업은 계속됩니다. 다시 연결하면 화면, 스크롤 기록, 커서와 터미널 모드가 복원됩니다.

## 설치 [#install]

**원격 호스트…**에서 SSH로 **서버 설치 / 업데이트**를 실행합니다. 같은 아키텍처의 Mac에는 내장 실행 파일을 사용합니다. Linux에는 해당 플랫폼과 아키텍처의 `zshell-server`를 선택하세요. 업로드와 호환성을 확인한 뒤 교체합니다. 실행 중인 daemon은 재시작까지 기존 버전을 사용하며 재시작하면 터미널 작업이 끝납니다. 호스트에서 직접 빌드할 수도 있습니다:

```sh
cargo build --locked --release --manifest-path remote/Cargo.toml
install -d "$HOME/.local/bin"
install -m 755 remote/target/release/zshell-server "$HOME/.local/bin/zshell-server"
```

연결자는 서버 실행 계정의 셸과 파일에 접근할 수 있습니다. macOS와 Linux를 지원합니다.

## SSH [#ssh]

일반 SSH로 호스트 키와 키 또는 agent 인증을 먼저 확인합니다.

```sh
ssh devbox true
```

사이드바의 네트워크 메뉴에서 원격 호스트를 열고 이름, `ssh://me@devbox:22` 또는 SSH 별칭, `~/.local/bin/zshell-server`를 입력합니다. 호스트 연결은 기존 프로젝트와 세션을 불러옵니다. `~/repo` 같은 원격 디렉터리를 입력하고 원격 프로젝트를 열면 새 셸을 만듭니다. 공백이 있는 경로를 지원하며 새 탭과 분할 창도 원격으로 실행합니다.

SSH는 daemon을 자동 시작하고 기존 OpenSSH 설정, 키, agent와 신뢰한 호스트 키를 사용합니다. 알 수 없는 키와 인증 실패는 오류로 표시되므로 일반 SSH에서 확인한 뒤 재시도하세요. 파일과 Git은 같은 호스트의 SSH를 사용하므로 Tailscale 터미널도 해당 패널에는 별도 SSH 인증이 필요합니다. 원격 경로는 Mac 파일을 가리키지 않습니다. `ZSHELL_SSH_CONFIG_FILE`로 읽을 수 있는 별도 설정 파일의 절대 경로를 지정할 수 있습니다.

## Tailscale [#tailscale]

두 장치를 Tailscale에 로그인하고 세션을 만들기 전에 비공개 리스너를 실행합니다.

```sh
zshell-server serve --listen tailscale://:7373
```

`tailscale://devbox:7373`를 추가합니다. MagicDNS와 Tailscale IPv4/IPv6를 지원하며 공개 주소는 거부합니다. 기본적으로 호스트 소유자의 태그 없는 장치만 허용합니다. `--allow-user`로 정확한 다른 로그인 이름을 허용할 수 있지만 태그가 있는 클라이언트는 거부합니다. 서버와 같은 장치에서는 SSH를 사용하세요. Tailnet ACL도 적용됩니다. 연결자는 서비스의 Unix 계정을 조작할 수 있습니다.

이 Mac을 공유하려면 Tailscale에 로그인하고 **원격 호스트… → 이 Mac 공유**를 선택하세요. 포트와 허용할 정확한 로그인 이름을 설정할 수 있습니다. 직접 시작한 경우에만 공유하며, **공유 중지**나 앱 종료는 공유 세션을 끝냅니다.

## 공유와 종료 [#sharing]

모든 클라이언트가 같은 출력을 받습니다. 터미널을 포커스하거나 제어권을 가져오면 해당 클라이언트만 입력과 크기를 제어합니다. 연결이 끊기면 가장 먼저 연결된 남은 클라이언트가 제어합니다. 정보 패널은 상태, 클라이언트 수와 제어권을 표시하며 분리와 재연결을 제공합니다. 네트워크 오류는 자동 재시도하고 오프라인 입력은 버립니다. 저장한 레이아웃은 원격 UUID로 같은 작업에 돌아갑니다.

창, 프로젝트, 패널을 닫거나 두 종료 옵션 중 하나를 사용해도 원격 세션은 분리만 됩니다. 원격 세션 종료는 확인 후 모든 클라이언트의 셸과 작업을 끝냅니다. 호스트에서도 `zshell-server terminate --project ~/repo --session UUID`를 실행할 수 있습니다.

Mac이 잠자기에서 깨어나면 공유 원격 세션이 연결을 확인하고 필요할 때 같은 원격 작업에 다시 연결합니다. 직접 분리한 세션은 분리 상태를 유지합니다.

## 파일과 스크린샷 [#paste]

일반 파일이나 스크린샷을 복사해 원격 창구에 붙여넣으세요. 호스트 비공개 디렉터리에 업로드한 뒤 세션 셸에 맞게 인용한 경로를 삽입합니다. 한 번에 32개, 파일당 32 MiB, 합계 64 MiB이며 폴더와 심볼릭 링크는 거부됩니다. 공유 업로드는 7일 보관됩니다. 일반 Unix SSH 창구도 지원합니다.

## 원격 Agent 대화 [#agents]

원격 Agent의 활동, 진행률, 승인 요청과 완료는 기존 창구 상태와 알림을 사용합니다. **Agent 대화 기록**에는 호스트의 Claude Code, Codex, OpenCode, Pi 대화가 포함됩니다. 재개는 실행 중인 대화로 연결하거나 원래 호스트와 디렉터리에서 정확한 세션을 시작합니다. 대화 기록은 daemon 재시작 후 유지되지만 실행 작업과 스크롤 기록은 유지되지 않습니다. 기존 프로그램, 설정이나 세션 파일이 필요합니다.

## 제한 [#limits]

daemon이 살아 있는 동안만 유지되며 호스트 재부팅, daemon 충돌이나 재시작은 넘길 수 없습니다. 사라진 세션은 새 셸로 대체하지 않고 오류를 표시합니다. 최대 128개 세션, 16 MiB 스냅샷, 클라이언트당 1 MiB 실시간 큐를 유지합니다. 느린 클라이언트는 다른 작업을 막지 않고 분리됩니다. 기록은 호스트 메모리에 보관됩니다. 서비스와 CLI는 [서버 설명](https://github.com/wzz6423/zshell/tree/main/remote)을 참고하세요.

## 브라우저 접근 [#browser-access]

**설정 → 브라우저 접근**에서 이 Mac의 로컬 터미널 패널을 브라우저로 조작할 수 있습니다. 기본적으로 꺼져 있습니다. 활성화 후 새 로컬 패널을 열고 로컬 페이지를 사용하거나 사설 IPv4 LAN/Tailscale 인터페이스와 HTTPS 포트를 명시적으로 선택하세요. 기존 패널은 현재 프로세스를 유지합니다. 브라우저는 Mac의 패널에만 연결하며 shell 생성이나 원격 호스트 연결은 할 수 없습니다.

다른 기기에서는 TLS 인증서를 내보내 설정의 지문과 비교하고 클라이언트에서 신뢰한 후 HTTPS 주소를 여세요. 이름을 입력하고 **페어링 요청하기**를 선택합니다. 2분 안에 Mac의 코드, 주소, 출처를 비교하고 **승인**하세요. 승인은 최대 90일이며 정확한 주소와 프로토콜에 한정됩니다. **승인 취소** 또는 **모든 클라이언트 승인 취소**는 연결을 즉시 끊고 기존 자격 증명을 거부합니다.

세션을 선택하면 현재 화면과 ANSI 색상·Unicode를 포함한 실시간 출력이 표시되며 같은 프로세스에 입력할 수 있습니다. Mac과 브라우저는 입력을 공유합니다. **브라우저 크기에 맞춰 터미널 조절**을 선택하지 않으면 크기는 Mac이 제어합니다. 연결이 끊긴 동안 입력은 버려지며 재연결은 살아 있는 같은 세션으로 돌아갑니다. 새로고침은 해당 탭의 자격 증명을 유지하지만 탭을 닫거나 **이 브라우저 잊기**를 선택하면 제거됩니다. 주소가 바뀌면 다시 페어링해야 합니다.

접근 비활성화, Mac 잠자기, Zshell 종료 시 브라우저 서비스가 멈춥니다. 패널을 닫으면 프로세스가 종료됩니다. 앱 종료 시 shell 보존은 `terminal.preserve-sessions`를 따르며 이 기능은 설정을 바꾸지 않습니다. Zshell을 다시 열면 살아 있는 패널에 접근할 수 있습니다. 호스트 재시작이나 데몬 종료는 shell을 끝냅니다. 출력 큐에는 한도가 있으며 느린 클라이언트를 끊어 Mac을 막지 않습니다. 페이지는 앱에 포함되며 CDN을 사용하지 않습니다.

이전 Zshell 버전이 보존한 세션이 실행 중이면 브라우저 접근은 모든 세션을 종료하고 앱을 다시 열도록 안내합니다. 사용자가 선택하기 전까지 기존 작업은 유지됩니다.
