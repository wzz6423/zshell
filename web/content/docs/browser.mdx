---
title: Browser panes
description: Open websites beside a terminal, navigate with native controls, and keep links inside the project.
---

Zshell can put a built-in browser in any tab or split pane. It is useful for a
local dev server, API documentation, an issue, or anything else you want beside
the terminal that is using it.

## Opening a browser

- Choose **File → New Browser Tab** for a blank tab.
- Open the command palette (<kbd>Cmd</kbd>+<kbd>P</kbd>) and run **New Browser
  Tab** or **New Browser Pane**.
- Command-right-click a detected URL in a terminal and choose **New Browser
  Tab** or **New Browser Pane** to open it without copying the address.

Browser tabs belong to the selected project and participate in its normal tab
and pane layout. If no project is open, Zshell creates one to hold the browser.

## Address and search

The field at the top accepts a full URL, a hostname, or search terms:

- `zshell.sh` becomes an HTTPS address.
- `localhost`, local hostnames, IP addresses, and explicit ports use HTTP.
- Everything else becomes a Google search.

Use <kbd>Cmd</kbd>+<kbd>L</kbd> to focus the field and
<kbd>Cmd</kbd>+<kbd>R</kbd> to reload. The toolbar also has Back, Forward,
Stop/Reload, Share, and **Open in Default Browser** controls. Trackpad back and
forward gestures work too.

| Action | Shortcut |
| --- | --- |
| Focus address bar | <kbd>Cmd</kbd>+<kbd>L</kbd> |
| Reload page | <kbd>Cmd</kbd>+<kbd>R</kbd> |

## Opening links where you want them

Right-click a link on a page for **Open Link in New Tab** or **Open Link in New
Pane**. The new page stays in the same project workspace.

In a terminal, a plain Command-click opens a detected web URL in your default
browser. Command-right-click is the version that offers a Zshell tab or pane.
Local paths have a parallel workflow described under
[Paths and URLs](/en/docs/terminal#paths-and-urls).

## What is preserved

Switching tabs or projects keeps the page as you left it, including history,
scroll position, forms, and in-page state. When Zshell relaunches, it restores
the current URL and layout, but not the full back/forward history.

Browser panes keep cookies, logins, and other site data across tabs and
launches. This is not a private-browsing mode.

## Let an agent test the page

Ask your coding agent to inspect the page already open in this project, fill a form, check a result, or capture its viewport. The agent uses the existing browser session and keeps focus in your terminal. It can also open a background browser pane for a local development URL.

For scripts, run these commands inside a Zshell terminal. Record the returned `browser_id` and replace `BROWSER_ID` below:

```sh
zshell +browser list
zshell +browser open http://localhost:3000 --wait
zshell +browser snapshot --browser BROWSER_ID
zshell +browser fill --browser BROWSER_ID --selector '#search' --text 'terminal'
zshell +browser click --browser BROWSER_ID --selector 'button[type="submit"]'
zshell +browser wait --browser BROWSER_ID --selector '#results' --timeout 10000
zshell +browser screenshot --browser BROWSER_ID --output /tmp/zshell-page.png
```

Snapshots return main-frame text, accessible labels, and element references. References expire after page changes or actions; take a new snapshot before reusing one. CSS selectors must match exactly one element. Use `navigate`, `back`, `forward`, `reload`, and `stop` for navigation.

Automation accepts explicit HTTP/HTTPS URLs and `about:blank`. Other protocols, downloads, file pickers, and native dialogs require your interaction. A page remains under this protocol restriction until you navigate manually with the address bar or toolbar. Commands stay inside the calling terminal’s project and window. `--timeout` is 100–30000 milliseconds. Snapshots are limited to 200 elements, 32768 text characters, and 256 KiB; password and file-input values are omitted. PNG viewport captures are limited to 512 KiB, require a pane that has been shown once, and never overwrite files. Reduce `--width` for a smaller capture. See `zshell +browser --help` for complete syntax.

## Ads and trackers

**Settings → Browser** enables native WebKit content blocking by default, using [EasyList](https://easylist.to/) and EasyPrivacy. Switch either list off independently, add custom HTTP/HTTPS ABP list URLs (one per line), and choose **Apply Lists**. Up to 8 lists of 8 MiB each are accepted. HTTP downloads are unencrypted.

Rules apply to future requests in all existing and new browser panes; reload open pages to update resources and hidden elements. **Update Lists Now** forces a refresh. Lists are cached locally; opening a browser after restarting checks lists older than four days. The settings show updates, converted/skipped filter counts, failures, and use of cached rules when a refresh fails. A failed replacement does not silently reuse a different selected list.

Supported filters include URL wildcards and anchors, common resource types, `@@` network exceptions, simple positive/negative domain scopes, and CSS `##`/`#@#` hiding rules. Domain scopes use the top-level page; party classification follows WebKit. Unsupported syntax is skipped conservatively, including scriptlets, procedural filters, redirects, regular expressions, document allowlisting, and scopes combining an included domain with excluded child domains. This does not provide full uBlock Origin compatibility.
