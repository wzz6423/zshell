Press <kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>E</kbd> for the file tree. Like the
git panel it's rooted at
[the project directory](/en/docs/projects#the-project-directory), so it doesn't
re-root every time you `cd`.

## The tree

With the Files panel visible and Zshell active, local directories refresh in the background. For SSH projects, Zshell periodically re-reads the remote root and expanded folders.

Click a file to open it in the focused pane. Right-click for the rest:

| Item | What it does |
| --- | --- |
| **Open** / **Open to the Side** | In this pane, or in a new split |
| **Open in Default App** | Hand it to whatever macOS opens it with |
| **Reveal in Finder** | |
| **Copy Path** | The absolute path |
| **cd Here** | Run `cd <folder>` in the focused terminal |
| **New File…** / **New Folder…** | Create inside the selected folder |
| **Rename** | |
| **Move to Trash** | To the Trash, not deleted outright |

Rows use filename-aware Material icons. Inside a Git repository, changed paths
also use status colors and badges, while ignored files are dimmed, so the tree
shows the same worktree state as the Git panel without opening it.

## Remote files [#remote-files]

Open SSH files from the Files panel. To create, rename, move to remote trash, or save, enable **Settings → Editor → Files → Allow remote file changes** (`files.remote-write-enabled`, off by default).

Zshell uses only tools already installed on the host and installs nothing. File reading and editing use the host’s existing Perl core modules. Each write operation also checks the filesystem capabilities it needs; unsupported operations stay disabled. The host resolves directory symbolic links in the project root and its ancestors once per file operation; symbolic links inside the project, special files, and paths outside the project are rejected. UTF-8 text files can be up to 5 MiB; remote Markdown opens as source.

Saving checks for remote changes even when local save protection is off. A conflict lets you compare, keep your draft, reload from the remote host, or approve an overwrite. Zshell rechecks the compared version immediately before publishing a complete file; an external process can still write after that final check.

**Move to Remote Trash** keeps contents and original-path metadata in the project’s private `.zshell-trash` directory. **Restore Last Remote Item** restores the last item during the current project selection without replacing an existing name. Older entries remain available for manual recovery from that directory.

## Import files and folders

Choose **File → Import Files…**, use the import button in the Files panel, or right-click a folder and choose **Import Files…**. Select one or more files or folders; Zshell copies them into that folder or the current tree root, keeping the originals.

To drop Finder items onto a folder or the tree’s empty area, turn on **Settings → Editor → Files → Import by dragging into the file tree** (`files.drag-import`). It is off by default. The menu remains available when dragging is off.

Existing names offer **Replace**, **Skip**, and **Cancel**. Replacing a folder replaces the whole folder, rather than merging its contents. Cancel stops the entire import and restores copies already added by that import. If another program changes an imported item before restoration, Zshell preserves the changed item and shows a folder that may contain recovery files. SSH trees accept no local imports. Symbolic links are copied as links; they are not followed.

## Find files and search contents

The command palette (<kbd>Cmd</kbd>+<kbd>P</kbd>) finds files by name or path
across the local projects open in the current window, alongside commands and
open sessions. Selecting a file switches to its project and opens it there.

To search the text inside files, click the magnifying glass in the Files panel,
or choose **Search File Contents** in the command palette. Enter text and press
<kbd>Return</kbd> to search the current local project directory. Use **Aa** to
match case, and open a result to jump to its matching line in the editor.

Content search matches literal text, skips binary files and common dependency
and build folders, and stops at 2,000 matches. You can stop a running search
while keeping its results, or close search to return to the file tree. SSH
projects are excluded from these local file searches.

## The editor

Opening a file gives you a real editor in a pane, with syntax highlighting.

| Action | Shortcut |
| --- | --- |
| Save | <kbd>Cmd</kbd>+<kbd>S</kbd> |
| Find | <kbd>Cmd</kbd>+<kbd>F</kbd> |
| Find and replace | <kbd>Opt</kbd>+<kbd>Cmd</kbd>+<kbd>F</kbd> |
| Find next | <kbd>Cmd</kbd>+<kbd>G</kbd> |

Closing a file, diff, project, or workspace window, or quitting Zshell, asks
whether to save unsaved edits. **Cancel** or a failed save keeps the affected
workspace and terminals open. In menu-bar mode, closing the last window only
hides it and keeps its edits; quitting still asks before discarding them.

Long lines wrap to the pane width by default. Disable
[`editor.wrap-lines`](/en/docs/configuration#editorwrap-lines) to scroll horizontally.

Renaming a file in the tree updates any pane that has it open, including files
underneath a renamed folder.

If another program changes an open file, Zshell refreshes a clean preview when
the app becomes active again. It never replaces an editor buffer with unsaved
changes.

If the file changes while you have unsaved edits, saving opens a conflict dialog. **Compare…** shows the disk version beside your draft; **Keep Draft** cancels saving, **Reload from Disk** discards your draft, and **Overwrite File** replaces the compared disk version. The same check applies when saving before closing and to editable worktree diffs. Control it with **Settings → Editor → Protect against save conflicts** or [`editor.protect-saves`](/en/docs/configuration#editorprotect-saves).

<Callout type="info">
This is an editor for the change you're already looking at — fix a typo, adjust
a constant, read a file the diff referenced. There's no language server, no
completion, and no project-wide refactoring. That's deliberate.
</Callout>

## Recover unsaved drafts

Zshell backs up unsaved local file and editable worktree diff changes by default. After an unexpected exit, reopened panes restore their drafts, selections, and layout. Recover other backups from **File → Recover Drafts…** or **Settings → Editor → Recover Drafts…**; select a backup, review its contents, and choose **Restore Draft**. Restoring opens an unsaved editor and never changes the file on disk. Saving still checks for external changes using the version from before your edits.

Control backups with **Settings → Editor → Back up unsaved drafts** or `editor.recover-drafts`. Turning it off stops new backups and automatic recovery, while keeping existing backups available for manual recovery or deletion. **Delete Backup** removes only the selected backup; open edits remain. Saving successfully or choosing **Don’t Save** for a completed close removes the backup. Backups are private files on this Mac, limited to 32 drafts and 128 MiB, recoverable for up to 30 days. Capacity limits may delete older backups sooner. Files and edited text larger than 5 MiB are excluded.

Zshell deletes expired backups at startup and every hour while running, even when backups are off. If Zshell is closed, expired files remain on disk until the next launch.

## Markdown preview

Open a `.md` file to read its rendered preview in the same pane. Click **Edit**
in the upper-right corner to work on its source, then **Preview** to see the
result. Zshell remembers your preferred mode for other Markdown files and the
next launch.

Switching modes keeps your edits and undo history. Save changes with
<kbd>Cmd</kbd>+<kbd>S</kbd> as usual. Markdown files with other extensions open
as source.

## Diffs

A diff opened from [the git panel](/en/docs/git) is just another pane, so a diff, a
file, and a terminal can sit side by side in one tab. It uses your terminal
font, and a thousand-file changeset opens as fast as a one-line one. Live,
unstaged worktree diffs can also switch from Review to Edit; staged and
historical diffs remain read-only. See [Reading diffs](/en/docs/git#reading-diffs).
