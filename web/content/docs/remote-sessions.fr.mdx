---
title: Sessions distantes partagées
description: Retrouvez le même terminal distant via SSH ou Tailscale, même après la fermeture du client.
---

`zshell-server` conserve le shell et ses tâches sur un hôte macOS ou Linux. Les deux moteurs de terminal de Zshell peuvent s’y connecter. Fermer le client ou perdre le réseau ne termine pas les tâches. La reconnexion restaure l’écran, l’historique, le curseur et les modes du terminal.

## Installation [#install]

Dans **Hôtes distants…**, choisissez **Installer / Mettre à jour le serveur** via SSH. Un Mac de même architecture utilise l’exécutable inclus. Pour Linux, choisissez le `zshell-server` compilé pour la plateforme et l’architecture. Le transfert et la compatibilité sont vérifiés avant remplacement. Un daemon actif conserve sa version jusqu’au redémarrage, qui termine ses tâches. Vous pouvez aussi compiler sur l’hôte :

```sh
cargo build --locked --release --manifest-path remote/Cargo.toml
install -d "$HOME/.local/bin"
install -m 755 remote/target/release/zshell-server "$HOME/.local/bin/zshell-server"
```

Le client peut agir avec le compte qui exécute le serveur. macOS et Linux sont pris en charge.

## SSH [#ssh]

Vérifiez d’abord la clé d’hôte et l’authentification par clé ou agent :

```sh
ssh devbox true
```

Dans le menu réseau de la barre latérale, ouvrez les hôtes distants. Saisissez un nom, `ssh://me@devbox:22` ou un alias SSH, et `~/.local/bin/zshell-server`. La connexion charge les projets et sessions existants. Pour créer un shell, indiquez un répertoire distant comme `~/repo` puis ouvrez le projet distant. Les espaces dans les chemins sont acceptés ; les nouveaux onglets et divisions sont également distants.

SSH démarre automatiquement le daemon et conserve votre configuration OpenSSH, vos clés, votre agent et vos clés d’hôte approuvées. Les clés inconnues et les échecs d’authentification sont signalés. Fichiers et Git utilisent SSH vers le même hôte, même si le terminal passe par Tailscale. Les chemins distants n’accèdent jamais aux fichiers du Mac. `ZSHELL_SSH_CONFIG_FILE` peut désigner un autre fichier OpenSSH lisible par un chemin absolu.

## Tailscale [#tailscale]

Connectez les deux machines à Tailscale puis démarrez l’écoute privée avant de créer des sessions :

```sh
zshell-server serve --listen tailscale://:7373
```

Ajoutez `tailscale://devbox:7373`. MagicDNS et les adresses Tailscale IPv4/IPv6 sont acceptés, les adresses publiques sont refusées. Par défaut, seuls les appareils sans étiquette du propriétaire de l’hôte sont autorisés. `--allow-user` ajoute un identifiant exact ; les clients étiquetés restent refusés. Sur la machine serveur elle-même, utilisez SSH. Les ACL du tailnet s’appliquent aussi. Un client autorisé peut agir avec le compte Unix du service.

Pour partager ce Mac, connectez Tailscale puis choisissez **Partager ce Mac** dans **Hôtes distants…**. Indiquez un port et, éventuellement, des identifiants exacts autorisés. Le partage démarre sur demande ; **Arrêter le partage** ou quitter Zshell termine les sessions partagées.

## Partage et fermeture [#sharing]

Tous les clients reçoivent la même sortie. Donner le focus au terminal ou prendre le contrôle accorde la saisie et le redimensionnement à ce client. À sa déconnexion, le premier client restant prend la main. Le panneau Informations affiche l’état, le nombre de clients et le contrôle, et permet de détacher ou reconnecter. Les coupures réseau sont réessayées automatiquement ; la saisie hors ligne est abandonnée. La disposition enregistrée retrouve le même travail par son UUID distant.

Fermer un panneau, projet ou une fenêtre, et les deux options de fermeture de l’application, détachent seulement les sessions distantes. Terminer la session distante demande confirmation puis arrête le shell et ses tâches pour tous. Sur l’hôte : `zshell-server terminate --project ~/repo --session UUID`.

Au réveil du Mac, les sessions distantes partagées vérifient la connexion et retrouvent le même travail distant si une reconnexion est nécessaire. Les sessions détachées manuellement le restent.

## Fichiers et captures [#paste]

Copiez des fichiers ordinaires ou une image et collez dans le panneau distant, ou déposez-y des fichiers. Zshell les envoie dans un dossier privé de l’hôte, puis insère des chemins distants protégés pour le shell sans exécuter de commande. Les images PNG, TIFF, JPEG, GIF et WebP deviennent des PNG ; seule la première image des animations est utilisée. Limites : 32 fichiers, 32 MiB chacun et 64 MiB au total ; dossiers et liens symboliques refusés. Les transferts partagés restent sept jours. Les panneaux SSH Unix ordinaires offrent les mêmes transferts.

Dans **Réglages → Terminal → Fichiers distants**, **Envoyer les fichiers et images copiés** (`terminal.remote-paste-upload`) et **Envoyer les fichiers déposés** (`terminal.remote-drop-upload`) sont activés par défaut. Désactivez une option pour arrêter ce transfert automatique ; aucun chemin local n’est inséré. **Envoyer des fichiers…** dans le menu contextuel du terminal distant permet toujours de choisir des fichiers. Reconnectez-vous et prenez le contrôle d’une session partagée avant l’envoi. Quitter le panneau, perdre le contrôle ou se déconnecter annule l’insertion en attente.

## Conversations Agent distantes [#agents]

Activité, progression, demandes d’approbation et fin des Agents distants utilisent les états et notifications existants. **Historique des conversations Agent** inclut Claude Code, Codex, OpenCode et Pi sur l’hôte. Reprendre reconnecte une conversation active ou lance sa session exacte sur l’hôte et dans le dossier d’origine. Cet historique survit au redémarrage du daemon, contrairement aux tâches et à l’historique du terminal. Le fournisseur et sa configuration ou son fichier de session doivent rester disponibles.

## Limites [#limits]

La persistance dure tant que le daemon fonctionne, sans survivre à son arrêt, son plantage ou un redémarrage de l’hôte. Une session absente est signalée, jamais remplacée silencieusement. Limites : 128 sessions, instantané de 16 MiB et file active de 1 MiB par client. Un client lent est déconnecté sans bloquer les autres ; l’historique reste en mémoire sur l’hôte. Consultez la [référence serveur](https://github.com/wzz6423/zshell/tree/main/remote) pour les services et le CLI.

## Accès par navigateur [#browser-access]

Dans **Réglages → Navigateur → Accès par navigateur**, activez l’accès aux volets locaux de ce Mac. Il est désactivé par défaut. Ouvrez ensuite un nouveau volet et utilisez la page locale, ou choisissez explicitement une interface IPv4 privée LAN/Tailscale et un port HTTPS. Les volets existants gardent leur processus. Le navigateur se connecte uniquement aux volets du Mac ; il ne crée pas de shell et ne se connecte pas à un hôte distant.

La page HTTP locale utilise normalement le port HTTPS configuré plus un (`7444` par défaut). La veille, Réessayer et la réouverture conservent cette adresse et son autorisation tant que la disponibilité des ports ne change pas. Si le port est occupé, Zshell essaie les sept ports locaux suivants ; après `65535`, la séquence reprend à `1024`. Si la disponibilité des ports change, un redémarrage peut sélectionner une autre adresse. L’autorisation existante est liée à l’origine précédente ; la nouvelle adresse nécessite donc un nouvel appairage. Les clients enregistrés restent visibles et révocables quand l’accès est désactivé. À la limite de 32 clients, révoquez-en un avant d’en approuver un autre. Si le service de sessions ne peut pas être vérifié, l’accès reste activé ; cliquez sur Réessayer lorsque le service est prêt.

Sur un autre appareil, exportez le certificat TLS, comparez son empreinte à celle des Réglages et faites-lui confiance avant d’ouvrir l’adresse HTTPS. Entrez un nom et choisissez **Demander un jumelage**. Dans les deux minutes, vérifiez le code, l’adresse et l’origine sur le Mac, puis choisissez **Autoriser**. L’autorisation dure au plus 90 jours pour cette adresse et ce protocole exacts. **Révoquer** ou **Révoquer tous les clients** coupe immédiatement les connexions et invalide leurs identifiants.

Choisissez une session pour voir son écran actuel et sa sortie en direct, avec couleurs ANSI et Unicode, et saisir dans le même processus. Le Mac et le navigateur partagent la saisie. Le Mac contrôle la taille tant que **Adapter le terminal à la taille du navigateur** n’est pas coché. La saisie hors connexion est abandonnée ; la reconnexion retrouve la même session active. Un rechargement conserve l’identifiant de cet onglet ; fermer l’onglet ou **Oublier ce navigateur** le supprime. Une nouvelle adresse exige un nouveau jumelage.

Désactiver l’accès, mettre le Mac en veille ou quitter Zshell arrête le service et déconnecte les clients. Fermer un volet termine son processus. La conservation du shell à la fermeture dépend toujours de `terminal.preserve-sessions`. Rouvrez Zshell pour retrouver les volets encore actifs. Un redémarrage du Mac ou l’arrêt du démon termine les shells. Les files de sortie sont limitées ; les clients lents sont déconnectés sans bloquer le Mac. La page est fournie avec Zshell et ne contacte aucun CDN.

Si des sessions conservées par une ancienne version tournent encore, l’accès par navigateur demande de quitter et terminer toutes les sessions, puis de rouvrir Zshell. Les tâches sont conservées jusqu’à votre choix.
