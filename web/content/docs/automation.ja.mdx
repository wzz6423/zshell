Zshell の自動化は、主に AI コーディングエージェント向けです。エージェントが Zshell のペインを操作し、別のエージェントと連携するための安全な手段を提供します。新しく覚える必要のあるコマンド言語ではありません。

AI 連携は標準で有効です。普段どおりエージェントと会話してください。現在使っているペインからフォーカスを奪わずに、バックグラウンドのペインを作り、作業担当を起動し、コマンドを実行し、結果を待って報告できます。

## 設定 [#setup]

**設定 → 自動化 → AI** を確認してください。標準でオンです。以前無効にした場合は再び有効にし、新しいターミナルを開くか、すでに実行中のエージェントを再起動します。

Zshell は Codex、Claude Code、Gemini CLI、Grok Build、OpenCode、Cursor Agent、Aider、Amp、Pi に対応します。
この機能と競合する既存のエージェント設定が見つかると、その設定は変更せず、スイッチを元の状態に戻し、設定画面にエラーを表示します。

## 普段の言葉で依頼する [#ask-in-plain-language]

求める結果をエージェントに伝えます。たとえば次のように依頼できます。

> 対象のテストをバックグラウンドのペインで実行して、失敗するものを教えて。

> この不具合を別の Codex エージェントに任せて、その結果をレビューして。

> API を担当するエージェントにスキーマの準備状況を聞き、テスト担当のエージェントに回答を渡して。

> 隣で開発サーバーを起動し、準備ができるまで待って URL を教えて。

> バックグラウンドのエージェントが完了したか確認して。止まっているなら、何が必要か教えて。

エージェントが代わりに Zshell の自動化インターフェースを操作します。自動化コマンドを入力したり暗記したりする必要はありません。

## ペイン間でエージェントを連携させる [#let-agents-coordinate-across-panes]

関連する作業を複数の Zshell ペインに分け、主担当のエージェントに調整を依頼できます。
たとえば一方が API、もう一方がテストの更新を担当します。調整役は特定の担当に発見事項を尋ね、追加依頼を送り、必要な結果を別の担当に渡して、まとめた回答を返せます。各担当は異なる対応コーディングツールでも構いません。

並行作業で文脈をコピーする手間を省けます。各エージェントは自分のペインで会話を保持し、調整役は相手に必要な質問、更新、結果だけを渡します。

追加依頼を送っただけでは作業完了ではありません。調整役は担当の完了を待ち、結果を読み、成果を確認します。
また、別のエージェントからのメッセージをあなたの承認として扱うことはありません。権限、認証情報、信頼の判断、破壊的操作は引き続きあなたが決定します。

## 実行中も作業を続ける [#keep-working-while-it-runs]

分担したペインは、表示を求めない限りバックグラウンドに留まります。提供元のネイティブなライフサイクル連携が状態を報告すると、Zshell はペインとタブに表示します。

| 状態 | 意味 |
| --- | --- |
| **実行中（Working）** | エージェントが作業を進めています。 |
| **対応待ち（Blocked）** | あなたからの入力、承認、その他の判断が必要です。 |
| **完了（Done）** | バックグラウンドで完了し、まだそのペインを表示していません。 |

Zshell が送信したプロンプトは**実行中**として記録しますが、その後の動作をターミナルの表示文字から推測することはありません。
**対応待ち**・**完了**への遷移と通知には、提供元からのライフサイクル報告が必要です。報告しないエージェントの場合は、推測された状態に頼らず、ペインとプロジェクトの変更を直接確認してください。

連携機能がエージェントの完了や入力要求を報告したとき、Zshell は通知を送ることもできます。
<kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>A</kbd> で、対応が必要と報告された次のエージェントへ移動します。

## アカウントの使用量と上限 [#account-usage-and-limits]

<strong>設定 → 自動化 → アカウント使用量（Account Usage）</strong>には、Claude Code と Codex の取得可能な利用上限を表示します。使用率、報告されている場合のリセット時刻、最終更新時刻を確認できます。
<strong>使用量を更新（Refresh Usage）</strong>で最新の取得可能なデータを読み直します。

Codex では、アカウントの上限を報告できる CLI がインストールされ、ログインしている必要があります。
Claude Code の使用量は、Zshell が提供元のステータスラインから使用量報告を受け取った場合に表示されます。
このセクションは使用量データがある場合だけ表示され、対応する集計期間は提供元とアカウントによって異なります。これはアカウントの上限であり、フォーカス中のセッションのトークン総数ではありません。

## 基本的な流れ [#a-typical-workflow]

1. Zshell ターミナルで普段のコーディングエージェントを起動します。
2. 範囲を絞った作業の分担、バックグラウンド処理、別のエージェントとの連携を依頼します。
3. 分担した作業がプロジェクトの配置に表示されている間も、現在のペインで作業を続けられます。
4. 利用できる場合は、提供元が報告する**実行中**・**対応待ち**・**完了**バッジを確認します。ライフサイクルを報告しないツールでは、ペインを開いて会話やターミナル出力を確認します。
5. [Git パネル](/ja/docs/git)で生成されたファイルと差分をレビューし、残す変更を決めます。

## 判断権はあなたにあります [#you-stay-in-control]

- エージェントの自動化は現在の Zshell プロジェクト内に限定され、別のプロジェクトやウィンドウのペインにはアクセスできません。
- 明示的に求めない限り、バックグラウンド作業がフォーカスを奪うことはありません。
- Zshell は権限、認証情報、信頼、破壊的操作の確認にあなたの代わりに答えません。提供元が対応待ちを報告したエージェントは、その判断をあなたへ返します。
- 完了の報告は結果をレビューする合図であり、エージェントの変更を自動承認するものではありません。

## エージェントが Zshell を使わない場合 [#if-an-agent-does-not-use-zshell]

- **設定 → 自動化 → AI** が有効か確認します。
- 有効化より前から開いていたターミナルなら、新しい Zshell ターミナルを開きます。
- 有効化した時点ですでに動いていたエージェントを再起動します。
- 設定画面にセットアップエラーが表示されていないか確認します。
- この流れで作業させたい場合は、「バックグラウンドの Zshell ペイン」や「Zshell の別のエージェントに分担」と明示して依頼します。
