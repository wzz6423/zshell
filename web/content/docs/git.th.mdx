กด <kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>G</kbd> แผงเปิด repository ที่โปรเจกต์ยึดอยู่ ดูวิธีเลือกที่[ไดเรกทอรีโปรเจกต์](/th/docs/projects#the-project-directory)

ทุกการกระทำเป็นคำสั่ง Git ที่ Zshell รันให้ และแสดงเอาต์พุตเมื่อมีมากกว่าเพียง “เสร็จแล้ว” จะไม่เขียนประวัติใหม่ squash หรือ force push หากคุณไม่ได้ขอ

## แถบเครื่องมือ Git [#the-git-toolbar]

Zshell แสดงแถบกะทัดรัดใต้แท็บที่ใช้งานได้ ใน repository จะแสดง branch ปัจจุบันและจำนวนบรรทัดเพิ่ม/ลบรวม หากไม่มีเปลี่ยนแปลงจะแสดง **สะอาด** สีเขียว ไฟล์ที่ยังไม่ track นับรวมเป็นบรรทัดเพิ่ม

- คลิกชื่อ branch เพื่อค้นหาและสลับ branch ในเครื่อง โดย branch เริ่มต้นของ repository มีเครื่องหมายกำกับ
- คลิกจำนวนการเปลี่ยนแปลงเพื่อเปิดแผง Git
- นอก repository โหมด **แสดงเสมอ** คงปุ่ม **ไม่มี Git repository** ซึ่งเปิดหน้าเริ่มต้น repository ของแผง

เลือก **ซ่อน**, **อัตโนมัติ** หรือ **แสดงเสมอ** ที่ **การตั้งค่า → ทั่วไป** หรือกำหนด [`toolbar.visibility`](/th/docs/configuration#toolbarvisibility) ค่าเริ่มต้นคือซ่อน ซ่อนแถบที่มองเห็นจากเมนูคลิกขวาได้ด้วย

## ไฟล์ที่เปลี่ยน [#changed-files]

ไฟล์แบ่งเป็นกลุ่มขัดแย้ง เปลี่ยนแปลงที่ stage แล้ว และยังไม่ stage เลื่อนเมาส์เหนือแถวเพื่อเห็นปุ่มหรือใช้เมนูคลิกขวา:

| ปุ่ม | หน้าที่ |
| --- | --- |
| **+** | Stage ไฟล์ |
| **−** | ยกเลิก stage |
| **↺** | ทิ้งการเปลี่ยนแปลงของไฟล์ |

**ทิ้งการเปลี่ยนแปลงทั้งหมด** อยู่หัวแผงและขอยืนยันก่อน นี่เป็นการกระทำที่ย้อนคืนด้วยคำสั่ง Git อีกคำสั่งไม่ได้

ไฟล์ขัดแย้งแสดง **ทำเครื่องหมายว่าแก้แล้ว (Stage)** แทนปุ่ม stage ปกติ เพื่อให้การแก้ขัดแย้งเป็นขั้นตอนที่ตั้งใจ

ปุ่มกรวยที่หัวแผงกรองตามชื่อไฟล์ เป็นวิธีเร็วที่สุดในการดูการเปลี่ยนแปลงขนาดใหญ่

## อ่าน diff [#reading-diffs]

คลิกไฟล์ที่เปลี่ยนเพื่อเปิด diff ในช่องข้างเทอร์มินัล ไม่ทับเทอร์มินัล เมนูคลิกขวามี **เปิดไฟล์** เพื่อเปิดตัวไฟล์ที่แก้ไขได้ และ **เปิดไฟล์ด้านข้าง**

Diff ขนาดใหญ่ยังตอบสนองเร็ว ชุดเปลี่ยนแปลงพันไฟล์เปิดเร็วเท่าหนึ่งบรรทัดและเลื่อนไม่สะดุด

ตัวควบคุมเหนือ diff จำสองค่าทั่วแอป:

- **รวม / แยก** สลับหนึ่งคอลัมน์กับสองฝั่งเคียงกัน
- **ตรวจทาน / แก้ไข** แสดงสำหรับไฟล์ที่ยังไม่ stage ใน worktree ปัจจุบัน แก้ฝั่งใหม่ได้โดยตรงแล้ว <kbd>Cmd</kbd>+<kbd>S</kbd> เพื่อบันทึก การปิดไฟล์ที่ยังไม่บันทึกเหมือนตัวแก้ไขทั่วไป

Diff ที่ stage และ commit ในประวัติยังอ่านอย่างเดียว เพราะเป็นสแนปช็อต ไม่ใช่ไฟล์ที่ Zshell เขียนได้อย่างปลอดภัย การสลับ diff หนึ่งเป็นแก้ไขหรือแยกอัปเดตค่าของ diff อื่นที่เปิด แต่ไม่ทำให้ diff ที่ไม่รองรับแก้ไขได้

## Commit [#committing]

พิมพ์ข้อความแล้วใช้ปุ่ม commit หรือเลือกจากเมนู:

- **Commit ที่ stage แล้ว** — commit เฉพาะสิ่งที่เตรียมไว้
- **Stage ทั้งหมดและ Commit** — stage ทุกไฟล์ที่ track แล้ว commit
- **แก้ไข Commit ล่าสุด** — รวมการเปลี่ยนแปลงที่ stage ไว้ใน commit ก่อนหน้า
- **Stage ทั้งหมดและแก้ไข Commit ล่าสุด**

Commit ล่าสุดอยู่ด้านล่าง เมนูคลิกขวามี **คัดลอก Commit Hash** และ **คัดลอกข้อความ Commit**

## Branch [#branches]

ชื่อ branch ที่หัวเป็นเมนู เลือก branch อื่นเพื่อสลับ หรือ **สร้าง Branch ใหม่…** เพื่อเริ่มจากตำแหน่งปัจจุบัน

## Worktree [#worktrees]

แผง Git แสดงทุก worktree ของ repository พร้อม branch และเส้นทาง checkout รายการที่ใช้งานมีป้าย **ปัจจุบัน** คลิก worktree เพื่อเปิดแท็บเทอร์มินัลใหม่ในไดเรกทอรีนั้น แต่ละ checkout จึงมีบริบท shell ของตนเองขณะที่ยังอยู่ในโปรเจกต์เดียวกัน รายการยาวเลื่อนในพื้นที่จำกัดของตัวเอง หัวส่วน ตัวควบคุม commit และรายการไฟล์ที่เปลี่ยนคงที่ คลิกหัว worktree เพื่อยุบ/ขยาย

Worktree ที่แยก HEAD แสดง **Detached HEAD** แทนชื่อ branch Repository แบบ bare แสดงเพื่อให้ครบ แต่ไม่มีไดเรกทอรีทำงานจึงเปิดเป็นแท็บเทอร์มินัลไม่ได้

## Remote [#remotes]

เมนู **⋯** รวมสิ่งที่ติดต่อ remote:

| การกระทำ | หน้าที่ |
| --- | --- |
| **Fetch** | อัปเดต ref ที่ติดตาม remote |
| **Pull (เฉพาะ Fast-forward)** | Pull โดยปฏิเสธการสร้าง merge commit |
| **Push** | ส่ง branch ปัจจุบัน |
| **เผยแพร่ Branch** | Push branch ที่ยังไม่มี upstream และให้เลือก remote เมื่อมีหลายตัว |
| **ซิงค์การเปลี่ยนแปลง** | Pull แบบ fast-forward แล้ว push |
| **Stash การเปลี่ยนแปลงทั้งหมด** | เก็บทุกอย่างรวมไฟล์ที่ยังไม่ track |
| **Pop Stash** | กู้ stash ล่าสุด |

ป้ายข้าง branch บอกจำนวน commit ที่ **↓ ตามหลัง** และ **↑ นำหน้า** upstream

เมนูเดียวกันมี **คัดลอกเส้นทางที่เปลี่ยน**, **คัดลอกเส้นทาง Repository** และ **แสดง Repository ใน Finder**

<Callout type="info">
Pull จำกัด fast-forward โดยตั้งใจ หากต้อง merge หรือ rebase จริง Git จะแจ้งและให้คุณตัดสินใจในเทอร์มินัล แผงไม่เลือกกลยุทธ์แทนคุณ
</Callout>

## ยังไม่มี Repository [#not-a-repository-yet]

หากไดเรกทอรีโปรเจกต์ไม่มี repository แผงเสนอ **เริ่มต้น Repository** ซึ่งรัน `git init` ในโฟลเดอร์นั้น ก่อนเริ่มต้นแผงจะไม่รบกวนการทำงาน
